## 一、本周工作梳理

本周开发重点由“搭建基础功能”转向“形成可连续游玩的展示版本”。团队围绕关卡推进、战斗反馈、角色与敌人表现、人格系统、仓库及中继通道、界面和演示稳定性进行了集中整合，并持续补充专项检查和开发记录。

### 1. 新增与完善内容

1. 完善三层普通关卡通往楼顶 Boss 的流程，继续补充 Boss 苏醒、守卫联动、阶段变化、攻击预警和胜利判定等内容。
2. 加入 Codex 服务通道及医疗补给、武器储藏、休息交互，使普通战斗楼层与后续关卡之间有较完整的过渡环节。
3. 扩展人格、协议和天赋相关内容，补充战斗通信、人格对白、状态面板、休息交互及不同人格的战斗反馈。
4. 完善重装盾兵屏障、远程敌人协同、环形盾反训练、旋转哨戒和多种战斗房型，增强敌人组合与战斗空间的差异。
5. 更新开始菜单、战斗 HUD、暂停与设置菜单、仓库终端、装备图标和品质显示，提升信息可读性及展示完整度。
6. 增加并整合玩家、敌人、武器、场景、音效和战斗特效资源，补充玻璃广告墙、灾焰武器、弹丸与命中反馈等可见内容。

### 2. 内容删减与调整

1. 收束早期占位内容和重复入口，将原先分散或仅供测试的交互逐步归并到正式的仓库、合成、服务通道和关卡流程中。
2. 调整旧版菜单、HUD、装备展示和仓库陈设，用能够反映实际游戏状态的界面与功能替换纯占位表现。
3. 根据试玩结果调整基础散热、敌人血量、近战攻击距离、屏障持续时间与冷却、房间出口位置和战斗空间，减少规则与画面表现不一致的问题。
4. 对尚未稳定、容易影响课堂演示的内容实行范围控制：课堂版本优先保证主流程、核心战斗和 Boss 展示，非关键扩展不再临时加入演示构建。

### 3. Bug 修复与稳定性工作

1. 修复暂停状态下转场淡入淡出不能正常结束、Boss 与房间遮挡关系异常、战斗 HUD 运行时回归等问题。
2. 修复敌人近距离攻击、远程敌人寻找掩护、敌方友伤、屏障与高速弹丸交互、炸弹在特定开关下失效等战斗问题。
3. 修复自动门、战斗出口、墙面标记、充能站提示和 Codex 通道背景的显示或位置问题。
4. 修复人格休息流程、医疗补给与武器储藏交互、装备和仓库界面衔接，以及场景切换后的状态保存问题。
5. 修复设置无法持续保存、菜单键盘导航不顺畅等问题，并继续维护相关集成检查。

### 4. 世界观与玩法设定完善

1. 进一步明确便携式 AI 人格、协议、天赋核心和断路保险之间的关系，使设定能够对应到实际战斗反馈和界面状态。
2. 补充 Codex 服务通道在关卡节奏中的功能定位，将补给、休息、人格交流和下一阶段准备集中到同一过渡空间。
3. 完善武器、义体、机动、防御组件和品质词条的说明，使装备成长与搜集—撤离—仓库—合成循环保持一致。
4. 统一普通楼层、楼顶 Boss 和仓库之间的推进逻辑，为课堂演示准备一条能够说明核心玩法的短流程。

## 四、安卓端迁移计划

团队计划在课堂展示版本稳定后，将项目逐步迁移到安卓端。迁移不直接等同于导出 APK，需分阶段完成：

1. **导出验证：**配置 Godot Android 导出环境、包名、签名和最低系统版本，先产出能够安装和启动的测试 APK。
2. **输入改造：**将键盘、鼠标操作抽象为可复用输入动作，增加虚拟摇杆、攻击、盾反、切换武器、交互和暂停等触控按钮。
3. **界面适配：**适配不同屏幕比例、分辨率、安全区域和触控尺寸，重点检查 HUD、背包、仓库、合成、设置及对白界面。
4. **性能优化：**检查移动设备上的粒子、光效、透明叠加、敌人数量、音频和资源加载，按实机表现设置画质档位。
5. **存储与兼容：**验证安卓端存档路径、应用权限、暂停恢复、切换后台、重新启动和不同设备上的兼容性。
6. **实机验收：**至少选择一台中低性能设备和一台主流设备，完成安装、更新、连续游玩、发热和耗电测试后再确定正式移动端范围。

## 五、课堂展示安排

课堂展示总时长为15分钟，按“5分钟 PPT + 5分钟实机演示 + 5分钟问答”执行。

### 1. PPT 汇报（5分钟）

- 0:00—0:25：封面及项目定位。
- 0:25—1:00：铁人叛乱、鱼灾、机械共同体和楼顶 DS 中枢的背景设定。
- 1:00—2:00：仓库整备、人格天赋、战斗拾取、撤离或继续上楼的完整流程。
- 2:00—3:00：完美防反、突进、射击热量和场地互动。
- 3:00—4:20：武器、义体、品质合成及战斗反馈。
- 4:20—5:00：总结核心玩法并切换到实机演示。

获批首版 PPT 共10页，其中包括1页封面、8页内容和1页实机演示过渡页。汇报时按现有页序讲解。安卓迁移属于后续计划，保留在会议纪要和问答准备中，不临时插入首版 PPT。

### 2. 实机演示（5分钟）

- 0:00—0:40：开始菜单、存档与设置。
- 0:40—2:40：普通战斗，展示移动、射击、盾反、敌人屏障和战斗反馈。
- 2:40—3:40：展示掉落、装备或 Codex 服务通道中的一项核心交互。
- 3:40—4:40：进入楼顶 Boss，展示阶段机制和视听表现。
- 4:40—5:00：总结当前版本闭环并退出演示。

演示前固定存档和操作路线；若现场流程出现意外，立即切换到对应节点存档或备用录屏，不在台上临时排查。

### 3. 问答环节（5分钟）

提前统一以下问题的回答口径：为什么选择 Godot、三人如何分工、AI 工具如何使用、核心玩法与同类作品有何区别、目前版本有哪些不足、为何及如何迁移安卓端。由最熟悉对应模块的成员主答，其他成员补充；无法确认的数据不现场猜测，会后再提供准确说明。

### 4. 展示前检查

1. 展示前至少进行两次完整计时彩排，确认 PPT 和实机演示均不超时。
2. 提前确认主讲、实机操作和问答记录人员，并准备一台备用电脑或备用视频。
3. 将展示构建、PPT、字体、视频和存档放在同一离线文件夹中，关闭自动更新和无关通知。
4. 展示当天只使用已验收构建，不临时合并新功能。
