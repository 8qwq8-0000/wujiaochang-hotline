# 导航、战斗提示与机动残影实施说明

> 状态：已实现并通过自动检查
> 日期：2026-10-15
> 参考评估：`docs/research/godotTestDemo系统复用评估.md`

## 1. 实施边界

本轮只吸收本地示例工程的设计思路，使用 Godot 4.7.2 和本项目既有架构重新实现，没有复制示例脚本、场景、图片、字体或音频。导航继续使用本项目的 `NavigationRegion2D + NavigationAgent2D`，没有引入第二套流场框架。

落地范围：

1. 敌人软避让、路径刷新节流、追击脱困和远程后撤候选；
2. 位于现有 HUD 底部中央的结构化战斗提示队列；
3. 轮胎、四足、飞行套件主动能力期间的池化角色残影；
4. 对应单元测试、真实场景集成检查与 16 敌人行为压力检查。

## 2. 敌人导航

### 2.1 主路径与软避让

`EnemyController` 仍由 `NavigationAgent2D` 取得下一路径点。控制器先计算期望速度，再提交给导航代理；收到 `velocity_computed(safe_velocity)` 后才执行移动。

软避让参数：

| 参数 | 值 | 用途 |
|---|---:|---|
| `radius` | 11 px | 与敌人身体半径一致 |
| `neighbor_distance` | 48 px | 只处理近邻，限制查询范围 |
| `max_neighbors` | 6 | 控制拥挤计算量 |
| `time_horizon_agents` | 0.5 s | 提前规避同伴 |
| `time_horizon_obstacles` | 0.35 s | 对静态障碍保持较短预测 |

敌人之间仍没有实体碰撞，因此不会互相推成死锁；RVO 只提供柔和分离。只有敌人中心确实落在导航网格附近时才启用 RVO，未配置导航区域的简易房间会回退到原有 `move_and_slide()`，避免有效 RID 但无可用多边形时速度归零。

攻击前摇、硬直、死亡和停止移动都会取消待处理的避让速度，防止延迟回调多移动一帧。

### 2.2 路径刷新

路径目标满足任一条件才重新提交：

- 距离上次刷新至少 0.1 秒；
- 目标相对上一次目标点移动超过 8 px；
- 新警戒、脱困或其他明确事件主动使路径失效。

该规则减少所有敌人逐帧重复写入同一目标的开销，又不会明显延迟对玩家位移的响应。

### 2.3 卡住恢复

敌人预期移动却连续约 0.75 秒几乎没有产生位移时：

1. 使当前路径失效；
2. 沿前进方向略向前，并依次尝试左右 28 px 的可导航候选点；
3. 候选点必须在导航面附近，且存在有效路径；
4. 使用候选点最多约 0.55 秒，抵达或超时后回归原目标；
5. 两侧都不可用时停止约 0.35 秒后再重试。

恢复过程不会传送、关闭碰撞或穿墙。

### 2.4 远程撤退

远程敌人距离玩家小于攻击距离的 65% 时，从背离玩家的 `0°、±30°、±60°` 扇区采样候选点。候选点必须可导航，评分以增加敌我距离为主并轻微惩罚过长路径；优先选择仍能与玩家保持无墙体遮挡的点，没有这类点时再使用距离评分最高的安全回退点。

## 3. 战斗提示队列

`CombatNotice` 定义消息 ID、文本、颜色、优先级、合并窗口和显示时长。`CombatNoticeQueue` 放在原有 HUD 的 `Overlay/NoticeQueue`，不接管 Dialogic 和接线员对白。

规则：

- 优先级为低、普通、高三档；
- 同时最多显示三条，高优先级在上；
- 超出预算时淘汰最低优先级中最早的一条；
- 带相同 ID 且处于合并窗口的消息合成 `文本 ×N`；
- 第一条真实消息出现后移除常驻操作教学；
- 场景树暂停时已有提示不计时，但背包操作仍可通过事件总线加入新提示；恢复游戏后统一继续倒计时；
- 旧的 `combat_message_requested(text, color)` 与 `publish_message()` 保留，由队列包装成普通优先级消息。

目前已把拾取／背包、过热／冷却、断路保险、玩家死亡和房间清理迁移为结构化提示。

## 4. 机动残影

玩家仅在轮胎、四足和飞行套件的主动能力持续时间内发射残影。步行没有套件能力，因此不会发射。

表现参数：

| 参数 | 值 |
|---|---:|
| 发射间隔 | 0.05 s |
| 单个淡出 | 0.25 s |
| 同时上限 | 6 |
| 颜色 | 青蓝色，初始透明度 0.55 |

残影直接快照 `PlayerVisualController.body_sprite` 当前帧、全局变换和左右／上下镜像；不复制武器、HUD 或格挡扇形。对象由现有 `VFXManager` 预热和循环复用，不在能力期间持续创建节点。

暂停会自然冻结残影淡出。切换或卸下机动套件立即停止继续发射，已有残影仍正常淡出；死亡、重开、导入运行状态和场景退出按玩家实例统一清理。

## 5. 事件接口

`CombatEvents` 新增：

- `combat_notice_requested(notice)` / `publish_notice(...)`；
- `afterimage_requested(source, sprite)` / `request_afterimage(...)`；
- `afterimages_clear_requested(source)` / `clear_afterimages(...)`。

玩法代码只发布意图，不直接查找 HUD 标签或创建特效节点。

## 6. 自动检查

单元检查：

```text
godot --headless --path . --script res://tests/run_unit_checks.gd
```

当前结果为 32/32 通过，新增覆盖：提示优先级／预算／合并／旧接口、残影快照／对象池／清理、敌人避让参数和无导航网格回退。

集成检查：

```text
godot --headless --path . --script res://tests/integration/enemy_navigation_check.gd
godot --headless --path . --script res://tests/integration/presentation_systems_check.gd
godot --headless --path . --script res://tests/integration/enemy_patrol_check.gd
godot --headless --path . --script res://tests/integration/enemy_alert_check.gd
godot --headless --path . --script res://tests/integration/enemy_loot_check.gd
```

16 敌人检查验证：所有敌人保持软避让、能够朝目标推进、不进入墙体或掩体内部，且任意一对不会连续完全重叠 0.5 秒。

无头检查不能替代目标最低配置的渲染帧率测量。正式验收仍需在最低配置机器的导出构建中，用 Godot Profiler 记录 16 敌人场景并确认稳定 60 FPS；24 和 32 敌人仅作压力参考，不作为当前基线。
