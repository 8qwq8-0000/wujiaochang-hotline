# 测试模式实施说明

## 使用入口

主菜单或暂停菜单打开“设置”，滚动到“测试选项”，开启“测试模式”，再点击“打开测试面板”。测试模式开启后，F8 或右上角按钮也可以打开面板。F8 或 Esc 关闭面板；面板打开期间暂停游戏。

## 支持的操作

- 领取正式武器、义体、防御装备及保险核心。武器和防御可选择制式、改良、原型品质。人格绑定武器仍通过对应人格获取，退役和内部调试道具不进入领取目录。
- 六格背包与保险核心唯一限制继续生效，领取失败不覆盖已有物品。关闭面板后使用 Tab 配装。
- 自由选择人格、1 至 3 级及各级天赋，选择完整验证后一次应用，不消耗人格饮料。
- 跳转测试仓库、三层普通关卡或楼顶 Boss。跳转保留当前测试配装、重置关卡并回满生命；普通层的直接跳转不强制打开人格饮料界面。
- 一键清理整个普通楼层，包括尚未激活的战斗区域。敌人仍发出正常的击败、掉落和清场事件，重型敌人直接完成死亡，不等待自爆。
- 直接击败 Boss，支持休眠、苏醒和守卫护盾阶段。出口和通关结算仍使用原有流程，可测试遗产记录展示。

## 存档隔离

`GameSettings` 创建常驻的 `TestTools` 面板，不修改项目自动加载配置。开关不持久化，程序重启后默认关闭。

`WarehouseStore.begin_test_session()` 保留进入前的正式档案快照。测试中的 `commit()` 继续校验装备与唯一实例 ID，但只更新内存，不创建、替换或重命名存档文件。测试中新建档案也不备份或覆盖正式文件。仓库、撤离、死亡、图鉴和通关记录共用这层隔离。

关闭测试模式会卸载当前游戏场景，恢复正式档案与原难度，再进入主菜单。恢复的正式档案在新主菜单读取之前生效。测试配装与记录不会带回正常游戏；本次测试关卡也不会续接为正式行动。请从仓库或主菜单进入测试，避免把尚未结算的正式行动当作已保存进度。

## 验证

新增集成检查：

```sh
godot --headless --path . --script tests/integration/test_mode_check.gd
```

覆盖设置开关和 F8、领取品质与容量限制、三人格全部天赋分支、非法选择无部分修改、仓库与楼层跳转、整层清场、Boss 开场与护盾阶段快速击败、结算与新建档案隔离、主菜单直达 Boss、死亡后跳关恢复，以及退出后正式档案和存档字节一致性。

同时运行原有 `settings_menu_check.gd`、`warehouse_check.gd`、`victory_flow_check.gd`，并检查实际渲染的设置页和测试面板。当前测试过程仍出现 Godot 退出时的资源／ObjectDB／RID 警告，以及已有敌人素材 UID 回退提示；这些提示尚未作为本次功能的一部分修复。Windows 与重新导出的独立游戏包未验证。
