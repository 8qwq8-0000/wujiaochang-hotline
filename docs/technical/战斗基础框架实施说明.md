# 《五角场热线》战斗基础框架实施说明

> 状态：v1.5 目标契约已更新；现有代码仍使用旧机动槽，迁移完成前不得把本说明视为已实现验收结果
> 实施日期：2026-10-13
> 引擎：Godot 4.7.2，GDScript，Compatibility
> 范围：脚本与场景，不包含第三方美术、音频或字体素材

## 1. 本次交付

本次把 GitHub 调研结果收敛为项目自有的薄组件架构，没有把任何大型示例工程整体复制进 `addons/`。当前主场景可以直接运行，并包含：

- 持久 `Main/SceneContainer` 与线程加载场景替换；
- 玩家移动、鼠标瞄准、三种武器接口和热量；
- 基础步行、Space 固有突进，以及已接入的单槽复合义体架构；
- 120° 方向格挡、完美格挡、弹丸反射和近战重硬直；
- 整数伤害、阵营、敌方友伤、击退和战斗事件管线；
- 三类普通敌人的共享控制器与数据配置；
- 楼层载入时一次性生成敌人的手工战斗房间；
- 不锁门、必杀敌人清零后启用出口电梯；
- 持久 HUD、伤害数字、命中/格挡矢量特效池；
- 对现有 SoundManager 的事件适配层；
- 战斗、固有突进、义体和房间抽取规则测试目标。

## 2. 运行入口与操作

主场景为 `res://scenes/bootstrap/main.tscn`，逻辑分辨率为 `640×360`，窗口覆盖尺寸为 `1280×720`。

| 输入 | 功能 |
|---|---|
| WASD | 移动 |
| 鼠标 | 瞄准 |
| 鼠标左键 | 使用当前武器 |
| 鼠标右键 | 开始一次格挡 |
| 鼠标滚轮 | 切换警棍、手枪、散射器 |
| Space | 固有突进；不依赖装备 |

旧原型中的数字键移动模式切换只用于迁移前调试，完成 v1.5 改造后删除，不进入正式 InputMap。

`bootstrap_main.gd` 会在开发期自检 InputMap。这样即使编辑器在 `project.godot` 改动后没有立即刷新，原型也不会持续产生“动作不存在”错误；正式输入配置仍保存在 `project.godot`。

## 3. 运行时层级

```text
Main
├── SceneContainer                 可替换内容场景
│   └── CombatPrototype
│       ├── FloorAssembler
│       │   └── PrototypeCombatRoom
│       └── Player
├── VFXManager                     持久特效池
├── AudioCueManager                持久音频事件适配
├── CombatHUD                      持久 HUD
├── TransitionLayer/Fade           场景过渡遮罩
└── SceneFlow                      线程加载与容器替换
```

`CombatEvents` 和 `RunManager` 注册为 Autoload。它们不持有具体玩家、敌人或房间节点，因此不会阻止场景释放。

## 4. 统一伤害管线

```text
Weapon / Projectile / Environment
                ↓
           DamagePacket
                ↓
         GuardComponent
       ┌────────┼─────────┐
   完美反射   普通格挡   未拦截
       └────────┴─────────┘
                ↓
       CombatFaction 倍率
                ↓
        HealthComponent
                ↓
          DamageResult
                ↓
 CombatEvents → HUD / VFX / Audio
```

### 4.1 DamagePacket

`DamagePacket` 是一次攻击的运行时值对象，包含：

- `base_damage`：基础整数伤害；
- `source`、`source_faction`：来源和阵营；
- `damage_type`、`status_tags`：扩展伤害与状态接口；
- `source_position`、`travel_direction`：正面判定和弹反方向；
- `knockback`、`stagger_seconds`：位移和失衡；
- `blockable`、`reflectable`：是否允许格挡或反射；
- `is_projectile`、`is_melee`、`is_area_damage`：攻击形态；
- `reflected`：反射后恢复完整敌方友伤倍率。

不要让武器直接扣血，也不要给某种武器写专用阵营例外。新增攻击必须构造 `DamagePacket`，交给目标 `HurtBox2DComponent.receive_hit()`。

### 4.2 阵营倍率

- 玩家攻击玩家：0；
- 普通敌方攻击命中敌方：0.6；
- 被完美格挡反射的敌方攻击命中敌方：1.0；
- 其他合法组合：1.0。

### 4.3 完美格挡时序

| 阶段 | 时长 | 能否攻击/再次格挡 | 结果 |
|---|---:|---|---|
| Startup | 0.06 s | 否 | 不能挡 |
| Perfect | 0.12 s | 否 | 反弹普通弹丸；重硬直近战攻击者 |
| Normal | 0.18 s | 否 | 抵消正面伤害 |
| Recovery | 0.22 s | 否 | 不能挡 |
| Idle | — | 是 | 可开始下一次格挡 |

方向判定以鼠标瞄准方向为中轴，左右各 60°。爆炸、地面范围伤害和背击不会进入格挡结果。成功完美格挡会请求 `HeatComponent` 降低热量，并通过事件产生金色波纹、消息和可选变调音效。

## 5. 玩家和武器

玩家场景：`scenes/actors/player/player.tscn`。

玩家节点只负责输入编排，具体能力位于子组件：

- `HealthComponent`：耐久；
- `HeatComponent`：热量、过热与恢复；
- `GuardComponent`：格挡状态机；
- `DashController`：固有突进的方向、冷却、无敌窗口、撞击和状态重置；
- `CyberwareController`：当前单件/复合义体的模块集合，以及攻击改造、持续射击和突进脱锁；
- `WeaponController`：当前武器、攻击节奏和生成攻击；
- `HurtBox`：所有受击入口。

三件原型武器使用 `WeaponComponentData`：

| 资源 | 类型 | 用途 |
|---|---|---|
| `baton.tres` | 近战 | 低热量、短距离、失衡测试 |
| `service_pistol.tres` | 单发弹丸 | 基准远程武器 |
| `scattergun.tres` | 多弹丸 | 过热、扩散和多命中测试 |

新增武器应新建 `.tres`，通常不需要新写控制器。真正需要新行为时，再扩展 `AttackKind` 或将生成行为拆成独立策略。

## 6. 固有突进与义体

### 6.1 固有突进

Space 始终可用，与右键格挡一样属于玩家固有主动技能。有移动输入时沿 WASD 方向突进，无输入时沿瞄准方向突进。目标基准为 `420 px/s`、`0.20 s`、约 `84 px`、冷却 `1.2 s`，前 `0.15 s` 无敌；撞墙提前结束并取消本次突进无敌。突进命中敌人造成 2 点伤害与约 `0.65 s` 硬直。旧 `MobilityController`、移动模式资源和数字键切换已从正式运行时移除。

### 6.2 单槽义体

`CyberwareController` 从义体槽当前物品读取模块集合。槽位为空时不提供效果；单件或复合义体可整体自由装卸，模块敲合后不可拆分，且单件复合义体最多集成四个不同模块。当前模块为：

- 智能火控：只改造可转向的普通实体弹丸，生成时锁定一次，不中途换锁；
- 爆裂弹仓：普通实体弹丸首次有效碰撞时附加一次范围伤害，已有范围攻击不重复附爆；
- 战术协处理器：兼容枪械按住连续射击，过热后停火，恢复到阈值后继续；
- 光学入侵器：突进时让索敌单位脱锁并追查最后位置，不撤销既有攻击。
- 击破散热器：玩家亲手击破敌人时移除 30% 最大热量，0.5 秒内的连续击破只触发一次；散热低于武器恢复阈值时立即解除过热。
- 热阈震荡器：武器进入过热时释放 64 px 无伤害震荡脉冲，使范围内普通敌人硬直 0.8 秒；内部冷却 8 秒且换装不会刷新。

义体没有品质、词条或升阶，行动结算时清除，不进入仓库或黑匣。具体行为边界以主策划案 5.3 和 15.2 为准。

## 7. 敌人、房间和楼层

### 7.1 敌人

三个敌人共享 `EnemyController`，区别全部来自 `EnemyProfile`：

- `melee_pressure.tres`：追击与近战施压；
- `ranged_sightline.tres`：保持射程并发射可反弹弹丸；
- `heavy_anchor.tres`：慢速、高耐久、大击退。

控制器状态为 `IDLE / CHASE / ATTACK / STAGGERED / DEAD`。场景已包含 `NavigationAgent2D`；当前无导航图时使用直接转向，后续手工房间加入烘焙导航区域后会自动使用路径下一点。

### 7.2 生成

`EnemySpawner` 在楼层/房间载入后立即读取全部 `EnemySpawnMarker` 并实例化敌人，不做玩家靠近才生成。标记保存：

- 角色标签；
- 敌人 Profile；
- 是否属于必杀目标；
- 可选点的激活概率。

随机内容只决定预先摆好的可选标记是否启用，以及后续可扩展的 Profile 池选择；不得在任意坐标凭空生成敌人。

### 7.3 房间与出口

`FloorAssembler` 从 `RoomTemplateData` 池按权重挑选手工房间，并放到固定间距插槽。当前原型使用一个 `prototype_combat_room.tscn`，后续扩展遵守：

- 统一尺寸和出入口坐标；
- 不旋转、不镜像；
- 不做自由拓扑和运行时导航烘焙；
- 门不因战斗锁死；
- 必杀敌人剩余为 0 后启用出口电梯。

## 8. 场景切换

项目继续保留 Maaack Scene Loader 1.7.0，供菜单或确实需要替换整棵 SceneTree 的流程使用。战斗区切换使用项目自有 `SceneContainerManager`：

1. 拒绝加载期间的重复请求；
2. `ResourceLoader.load_threaded_request()` 后持续发布进度；
3. 淡出；
4. 释放 `SceneContainer` 旧内容；
5. 实例化新 `PackedScene`；
6. 传递 payload；
7. 淡入。

不要修改 `addons/maaacks_scene_loader`，避免以后升级覆盖项目逻辑。

## 9. HUD、VFX 与音频

HUD 是持久 `CanvasLayer`，读取玩家组件的公开状态，不直接访问 GLoot 内部字段。当前显示耐久、热量、武器、机动、格挡阶段和必杀敌人数。

`VFXManager` 预热并复用两类纯脚本场景：

- `EffectFlash`：命中、普通格挡、完美格挡；
- `DamageNumber`：整数伤害数字。

默认总预算为 64。池满时复用最早效果，不删除任何权威战斗实体。

`AudioCueManager` 只做 `CombatEvents → SoundManager` 映射。当前没有加入音频素材；配置 `perfect_guard_sound` 和 `hit_sound` 后即可使用现有 SoundManager 的播放器池。连续完美格挡会在 1.2 秒链中逐步提高音高。

## 10. 测试和验收

`tests/` 当前覆盖：

- 敌方友伤与反射倍率；
- 120° 正面完美格挡和背击绕过；
- 整数伤害扣除；
- 四种移动模式边界；
- 房间权重抽取边界。

每次修改战斗基础层后至少完成：

1. 运行全部 `test_*.gd`；
2. 启动 `main.tscn`，确认无解析或运行时错误；
3. 用敌方射手验证普通受击、普通格挡和完美反弹；
4. 切换四种移动模式，确认 HUD 同步；
5. 清理必杀目标，确认出口从红色变为绿色。
