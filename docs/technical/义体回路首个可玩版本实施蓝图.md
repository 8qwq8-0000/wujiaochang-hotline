## 1. 目标与边界

首个可玩版本不追求一次交付全部 20 件义体、长期经济和 18 项天赋。它只需证明三件事：

1. 玩家能把义体排成有序回路；
2. 顺序、修正、武器调用、格挡调用和固定回能会产生可见的组合差异；
3. 能量、队列、执行快照和战斗中编辑在真实 Godot 运行中可靠。

### 1.1 首版不做

- 不接入完整敌人掉落、算力、蓝图研究和终端；
- 不实现其余 11 件义体；
- 不改造 18 项人格天赋；
- 不执行灾厄之炎武器迁移；
- 不交付移动端最终排版；
- 不修改与本子系统无关的美术、VFX、敌人或关卡。

## 2. 首版内容

### 2.1 义体集合（9）

- 主动神经开关；
- 战斗突触感应器；
- 节律脉冲器；
- 智能火控；
- 爆炸弹匣；
- 战术协处理器；
- 击杀热沉；
- 格挡协处理器；
- 指令镜像突触。

### 2.2 试验场入口

复用现有隔离测试模式，增加“义体构筑试验场”入口。进入时：

- 发放首版 9 件义体的足量测试副本；
- 开放 4 槽回路；
- 当前能量与上限为 100，回复为 40/s；
- 提供不可破坏靶、可射击敌人和近战敌人；
- 可重置能量、热量、回路与敌人，但该操作只存在于隔离测试模式。

## 3. 最小运行责任

实施优先沿用现有 `CyberwareData`、`CyberwareController`、战斗事件和玩家存档结构，只在旧责任无法承载新语义时拆分。首版需要五个逻辑责任，不要为每件义体新建一层管理器：

1. **定义数据**：ID、等级、耗能、标签、图标、效果参数和兼容性；
2. **回路编译**：验证持有数、生成快照、解析镜像来源、计算真实顺序和预付门槛；
3. **运行执行**：能量、三类队列、槽位步进、修正传递、武器/格挡适配和反馈事件；
4. **义体库与装配**：持有数、安装消耗、卸下返还、跨场景状态；
5. **呈现**：编辑器、HUD 指针、待消耗修正、队列/能量状态和战斗反馈。

数值结算和游戏规则不写在 UI 中；UI 只读取编译结果和运行快照。

## 4. 实施阶段

**改动边界**：不实现实际战斗效果，不改 UI 美术。  
**退出条件**：单元测试证明顺序、副本数、固定回能预付、能量不足等待和状态导入/导出。

**输入**：BP-01 的编译计划、现有武器/格挡/伤害接口。  
**输出**：三启动器、三格请求队列、9 件义体、可见槽位步进。  
**改动边界**：不实现经济、人格天赋或禁忌回绕。  
**退出条件**：集成测试证明修正消耗、武器调用、赛博格挡、镜像、轮后事件与防递归。

### BP-03 编辑器与 HUD

**状态（2026-11-03）**：已通过自动化门。24 项真实 UI 集成断言覆盖按键、暂停、独立库存、编译预览、战斗中编辑快照、640×360 边界、右下运行状态和显式指针；窗口主观可读性由驾驶员自行确认。  
**输入**：可查询的编译结果与运行状态。  
**输出**：`C` 暂停编辑、独立义体库、实际顺序/净耗能预览、右下 HUD 和显式指针。  
**改动边界**：`E` 继续交互，`Tab` 继续背包，不做移动端最终排版。  
**退出条件**：编辑中旧轮快照不变，新排列下轮生效；640×360 无截断、指针可读、能量/队列状态与运行一致。

### BP-04 隔离试验场与真实运行验收

**状态（2026-11-03）**：实现与自动化已通过。试验场专项 15 项零失败；完整测试模式 89 项零失败并验证正式存档隔离。驾驶员试玩清单仍待亲自确认。  
**输入**：BP-01—03 的完整核心链。  
**输出**：现有测试模式内的义体试验场、自动化回归、可供驾驶员亲手试用的构筑。  
**改动边界**：不绕过正式战斗伤害、武器和格挡管线；测试重置操作不进入正式行动。  
**退出条件**：自动化证据、真实 Godot 运行证据和驾驶员试玩清单均齐全。

## 5. 必须通过的构筑样例

1. `主动神经开关 → 智能火控 → 爆炸弹匣 → 战术协处理器`  
   预期：按 `F` 后耗能 50，当前武器发射可追踪并在首次命中时爆炸。

2. `战斗突触感应器 → 格挡协处理器 → 指令镜像突触`  
   预期：战斗事件启动后连续调用两次同参数格挡；成功完美格挡的新事件在本轮后入队。

3. `节律脉冲器 → 击杀热沉 → 指令镜像突触`  
   预期：编译预览明确显示耗能、两份固定回能和净门槛；无击杀标签时不预计额外条件回能。

## 6. 失败路径验收

- 能量不足：请求保留，达标后自动执行；
- 启动前武器过热：含武器调用的请求等待；
- 执行中编辑：旧快照完成，新排列下轮生效，不退能量；
- 赛博完美格挡：事件轮后入队，不在当前轮里开新轮；
- 镜像启动器：只复制基础脉冲；
- 镜像相邻镜像：一直指向最近的原始非镜像指令，不递归；
- 死亡/切场景/重开：无效队列、执行快照和临时修正清理，不污染新场景；
- 空槽、义体数量不足或存档缺少定义：拒绝无效排列并给出可见提示，不崩溃。

## 7. 验收证据

### 7.1 自动化

- 编译器单元测试：顺序、镜像、预付、副本数、无效排列；
- 运行单元测试：40/s 回复、三格队列、覆盖、优先级、死亡清理；
- 战斗集成测试：射弹修正、武器调用、格挡调用、反馈事件和防递归；
- 存档测试：库、排列、能量、队列和旧数据的可控导入。

### 7.2 静态与界面

- 资源引用与 Godot 编辑器扫描无新错误；
- 640×360 编辑器与 HUD 截图；
- 指针、修正挂载、队列状态和净门槛与运行日志一致。

### 7.3 真实宿主与驾驶员

在真实 Godot 运行试验场完成三个必测构筑、一次能量不足等待、一次执行中编辑和一次赛博完美格挡。驾驶员确认：

- 顺序差异能被直观感知；
- 不看日志也能判断当前执行到哪；
- 等待原因和净耗能可理解；
- 愿意主动重排一次回路以改变效果。

自动化、截图或开发者自评不能代替驾驶员验收。
