# 退出资源清理回归记录

日期：2026-11-11。环境：macOS，Godot 4.7.2 stable。

## 修复

- GLoot 原型树解除父子索引的循环引用，并在脚本虚拟机仍可执行清理时释放静态缓存。新增嵌套继承弱引用回归，保留外部子节点的继承属性访问。
- HUD 的隐藏保险状态 Label 加入节点树管理；单元测试创建的 HeatComponent 纳入夹具回收。
- 音频池取消 Tween 对自身的回调绑定，退出节点树时停止播放器并释放 stream。
- 菜单退出和窗口关闭统一进入幂等的 `GameSettings.quit_game()`：停止节点处理和播放，释放 stream，等待 100 毫秒真实时间供音频服务回收，再退出。重复关闭不会覆盖第一次退出码。真实时间等待不会被固定帧率或游戏时间倍率加速，期间继续运行主循环。
- 当前引擎的线程加载对照测试残留 8 个 RefCounted；同步加载对照退出干净。场景容器与菜单 SceneLoader 改为同步加载，保留下一帧调度、淡出和信号接口，避免改变新开局种子及人格休整的初始化顺序。相关引擎修复参考 https://github.com/godotengine/godot/pull/121025 。代价：未缓存场景加载期间会占用主线程，楼层切换在淡出后执行。
- 修正 enemy.tscn 对 melee_frames.tres 的过期 UID。

## 验证结果

- 18 个单元测试套件，共 115 个测试全部通过；退出详细日志无诊断。
- 当前背包、合成、序章、仓库、跨层、撤离、回路、移动端交互、补给台、地图、环境物件和 Boss 等 48 个集成脚本全部通过；同时检查退出日志，0 警告、0 错误、0 泄漏报告。
- `python3 tools/check_shutdown.py`：菜单按钮、战斗关闭、暂停关闭、加载关闭、SceneLoader 后台加载后关闭，5/5 干净退出。
- `python3 tools/check_shutdown.py --windowed`：同样 5/5 干净退出，包含图形及音频驱动。关闭用例通过派发系统关闭通知验证，没有自动点击 macOS 标题栏关闭按钮。
- `git diff --check` 通过。

无窗口与窗口退出探针均检查完整进程退出后的 verbose 日志，不禁用音频、不关闭泄漏检测、不过滤清理警告。集成夹具采用正式的有序退出入口，不再直接越过音频回收调用 SceneTree.quit。

本结果限于本机现行用例；不代表移动设备或其他系统的退出也经过实机验证。旧 API 的历史夹具未计入这 48 个入口。


## 主分支整合与 Boss 反馈补充复查

整合主分支后单元测试增加至 119 个，全部通过。现行集成脚本扩展至 63 个，全部通过并检查进程退出日志。Boss 反馈的 22 项检查已包括在内；两场原有 Boss 检查分别 49、76 项通过。菜单、普通战斗、暂停、加载、SceneLoader、普通 Boss 和第二结局 Boss 的退出探针，在无窗口/窗口模式分别 7/7 通过，共 14 次干净退出。

同时修复了 Dialogic 时间线与变量编辑器创建的 UndoRedo 未 free 问题：编辑器退出不再报告两个 ObjectDB 对象泄漏。编辑器 verbose 模式仍有一个 Node StringName 未认领提示，属于尚未清零的编辑器诊断；游戏运行退出不出现该提示。此处明确保留该限制，不把编辑器验证写成完全无诊断。
