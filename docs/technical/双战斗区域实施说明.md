# 双战斗区域

正式战斗场景 `scenes/levels/floors/combat_prototype.tscn` 现在包含两个横向相连的区域。仓库出击进入第一区；击败第一区的必杀目标后，右侧通道解锁，沿绿色箭头走进第二区开始下一场战斗。第二区清场后，右侧最终出口提供继续下一层、撤离返回仓库的选择。R 重开会同时重置两个区域。

## 行为

- 每区各有一只炸弹箱、一只配电箱。正式关卡不放自动门；通道仅有清场封锁线。
- 第二区敌人在玩家实际进入时生成。全层必杀目标计数包含待进入区域，第一区清场不能提前结算撤离。
- 两区共用玩家实例，穿过通道不恢复生命、热量，不重建装备、背包或冷却，也不递增楼层。
- 配电箱增益只绑定所属区域，本区清场时失效；第二区可独立领取自己的增益。
- 已清场区域允许换装；进入未清场区域恢复战斗换装限制。第二区敌人的目标检测与警戒限制在本区。
- 敌人死亡原地概率掉落组件（默认 20%）；若第一区直到最后一只仍未掉落，则由该敌人补出本层保底。已掉过后清场不再另发固定补给。后续区域敌人仍可概率掉落，品质与词条按楼层抽取。详情见[品质词条合成与正式掉落实施说明](品质词条合成与正式掉落实施说明.md)。
- HUD 显示当前区域序号与本区剩余必杀目标，清场后提示前往下一区；仅两区都清场后显示全层出口提示。

## 接入

`FloorAssembler.sequential_progression` 默认关闭，保持独立房间/测试场景原有行为；正式场景启用并设置 `room_count = 2`。第一区初始激活，后续区域通过世界坐标进入检测激活。`EnemySpawner` 缓存本次种子的生成计划，待激活目标可以提前计数而不会提前生成敌人或重复抽签。

相邻原型房间侧墙保留上下碰撞段，中间留出通道，由 `CombatPassage` 管理封锁碰撞、提示和导航连接。当前连通布局使用原型房间的 640×360 尺寸及水平间距，不适用于任意形状房间模板。

## 验证

```sh
godot --headless --path . --script res://tests/integration/dual_area_check.gd
godot --headless --path . --script res://tests/integration/extraction_check.gd
godot --headless --path . --script res://tests/integration/restart_room_check.gd
```

专用检查通过真实物理帧移动验证封锁与通行，同时验证区域激活、目标累计、生命/热量/装备保留、两次独立增益、全层唯一保底、防重复死亡信号、换装限制与最终出口。现有通关、掉落、场景切换、仓库和撤离检查已按两区流程更新。
