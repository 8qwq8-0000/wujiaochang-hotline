# 组件、背包与掉落原型

> 2026-10-18：品质、词条、合成及正式保底已落地，当前规则见[品质词条合成与正式掉落实施说明](品质词条合成与正式掉落实施说明.md)。本文保留早期原型接入记录，下文每敌人固定掉落和未实现品质等描述属于历史状态。

本次实现对应成员 B 的基础物品闭环。物品存储使用现有 GLoot 的公开 API，项目规则集中在 `ComponentInventory`，没有修改插件源码。本分支基于已合并 R 键重开功能的 main。

## 试玩

只测背包时，打开 `scenes/levels/inventory_test_room.tscn` 按 F6：无敌人，地上有七件测试组件，可直接换装和验证满包。

F5 运行项目。玩家初始只有一件绑定警棍，直接装备在主武器槽，不占背包格（开局 0/6）；副槽为空，机动为基础步行。出生点不再预放手枪或轮式组件，新增物品来自敌人掉落。

1. 靠近地上的组件，出现名称和 E 提示后按 E 拾取；不能隔墙拾取。每局第一次成功拾取武装组件时，若副武器槽为空，直接装入副槽，不受清场限制且不占背包格；背包满时仍可直接装入空副槽，后续普通拾取遇到满包时失败并保留地上物品；当前武器不强制切换，可立即按 Q 或滚轮使用。副槽已有武器时不自动替换，拾取物进入背包。后续武器拾取仍进入背包，即使副槽后来清空也不再触发此例外；新一局重置首次拾取资格。
2. 按 Tab 打开六格背包；Tab 或 Esc 关闭。打开时全图暂停，敌人、子弹、热量与冷却计时停止，背包界面仍可操作；Tab/Esc 关闭后恢复。暂停不会自动解除清场换装限制。
3. 清场后将背包物品拖到主武器、副武器或机动槽，拖回背包卸下；目标已有物品时在类型兼容的前提下交换。界面不使用目标下拉框。黑匣是单独的保护槽，允许在战斗暂停的背包中拖动调整。点击物品快速装备和点击装备槽卸下仍可使用。
4. 除首次武器填入空副槽外，满包时拾取失败，地上物品保留。主武器、副武器和机动组件都使用独立装备槽，不占背包格；装备到空槽会释放一个背包格，替换时把旧装备交换回原背包格，因此满包仍可替换。满包时不能卸下任何装备，需先腾出空位。
5. 装备武装改变实际攻击，装备轮式组件改变移动和主动能力；卸下武器将物品移回背包并占一格；若两个武器槽都为空则无法攻击。卸下机动恢复基础步行。Q/滚轮可在战斗中切换主、副槽已携带的武器，空副槽跳过；切换不重置攻击冷却或热量，暂停查看背包时与死亡后均不能切换。数字键不能绕过装备获取其它武器和机动模式。
6. 敌人死亡掉落一个测试组件：近战掉警棍、远程掉手枪、重装掉轮式组件。
7. 按 R 重新开始，背包、装备、掉落和旧场景一并清空，并重置首次武器拾取资格。

这些是确定掉落的测试组件，不代表最终品质、随机词条、合成、撤离结算或存档系统。当前只有三个武装与一个机动组件原型；仓库、黑匣、正式机动组件池后续实现。

## 文件与接口

- `resources/items/components.json`：GLoot 物品原型（名称、图标、槽位、效果资源）。运行时实例单独保存 instance_id，不修改共享资源。
- `scripts/gameplay/inventory/component_inventory.gd`：六格约束、拾取、满包安全换装与清场换装规则。三个独立 GLoot ItemSlot 分别持有主武器、副武器和机动组件；物品在背包与装备槽之间移动或交换，不能重复存在于两处。
- `scripts/gameplay/items/component_pickup.gd` / `scenes/items/component_pickup.tscn`：E 交互和距离/遮挡检查，component_id 指定物品。
- `scripts/ui/inventory_panel.gd`：简单六格界面及主武装、副武装、机动三个装备槽，点击和文字反馈。
- `WeaponController.set_carried_weapons(primary, secondary)` / `MobilityController.set_equipped_mode(mode)`：可供玩家负责人继续接入的换装接口；主武装传 null 清空主槽，副武装传 null 清空副槽，机动传 null 恢复步行。旧的 set_equipped_weapon(data) 接口仍保留给单武器接入。
- `scripts/gameplay/items/enemy_loot.gd`：监听 CombatEvents.entity_defeated，按敌人角色确定测试掉落；快照死亡位置并延迟生成，标记确保不会重复掉落。随玩家实例创建，支持单独运行房间。
- 原创 SVG 图标位于 `assets/art/items/`；原创短音效位于 `assets/audio/sfx/enemy_ui/`，`tools/generate_inventory_sounds.py` 可重新生成。

## 敌人修复

- 远程敌人在可见目标进入射程后原地预警并射击，近距离也不后退；沿用原有预警、射击冷却与掩体检查。
- 导航先设置目标再查询路径，避免初始路径完成状态阻止追踪。
- 原型房间增加离线烘焙导航资源（7 个多边形），避开两处掩体；不在运行时烘焙。地图碰撞改变后需由关卡负责人重新烘焙。
- 攻击增加约 0.4 秒预警、方向线与提示音；近战预警期间离开攻击范围可以躲开，受硬直会中断准备。
- 掩体阻挡攻击视线，子弹移动使用墙体射线扫掠避免高速穿墙。

## 队友房间接入

`feature/week1-scene` 的关卡和素材已接入，并以当前玩家、敌人、背包与重开接口为准完成兼容。该场景现已作为正式“仓库出击”和“继续下一层”的目标；原型楼层继续保留给开发回归。原始 `week1-inventory-integration.patch` 保留为历史接入参考，不再需要手动应用。

接入将碰到即消失的占位组件替换为真正的 E 拾取组件；按 `enemies` 分组统计房间内实际敌人；适配携带 `DamagePacket` 的死亡信号；同步 `RunManager` 目标计数；导入仓库传入的玩家配装；清场后启用真实撤离电梯；通过 Main 加载时由 Bootstrap 负责 R 重开，F6 单独运行时由房间负责重载。

当前场景实例化 **2 个近战敌人**，目标计数不再硬编码。房间布局和原始二进制素材保持不变。运行以下检查时必须实际通过，SKIP 不计为成功：

```sh
godot --headless --path . --script res://tests/integration/week1_room_check.gd
```

## 验证与限制

- inventory_check：六格容量、满包交换、唯一实例、地面物品保留、重复拾取保护、死亡限制、Tab/Esc。
- enemy_loot_check：远程近距离停留与实际射击、冷却、绕障碍、预警与躲避、掩体阻挡、单次掉落和装备后实际射击。
- playthrough_check：连续三次主场景完整物品流程及 R 重开后的数据重置；通过面板按钮验证选中索引。
- weapon_slot_refill_check：主、副武器均卸下后，连续装备会依次填入两个空槽；两槽已满时不会覆盖玩家手动选择的替换目标。
- restart_room_check：原来的正常战斗、死亡、清场三种重开回归。
- 原有三套单元测试共 10 项。
- week1_room_check：验证接入后房间的 F6/主场景两种运行方式、实际敌人数、真实拾取、清场掉落与重开；SKIP 不计为通过。

主场景自动化检查退出时仍有 6～10 个 ObjectDB 实例的释放警告，没有将其当作修复完毕。Mac 上已生成并查看实际渲染截图；Windows 运行及最终音效试听仍需团队人工验收。
