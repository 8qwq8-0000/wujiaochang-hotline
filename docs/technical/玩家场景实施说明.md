# 玩家场景实施说明

> 负责人：沈宝硕（A 工作）<br>
> 场景入口：`res://scenes/actors/player/player.tscn`<br>
> 独立验收：`res://scenes/debug/player_sandbox.tscn`<br>
> 状态：v1.5 现行接口；玩家场景已使用 `DashController` 与 `CyberwareController`

## 1. 场景边界

玩家场景只封装玩家实体。正式房间、敌人、掉落和流程结算均由外部场景管理。根节点原点为脚底锚点，世界碰撞只覆盖脚部，受击框独立覆盖身体。

主要节点：

- `HealthComponent`：3 格基础耐久、修复、死亡和致命伤害拦截；
- `HeatComponent`：枪械热量与过热；
- `GuardComponent`：右键单次格挡时序及完美格挡；
- `DashController`：固有突进方向、冷却、无敌、撞击和落点；
- `CyberwareController`：义体模块集合、攻击改造、持续射击与突进脱锁；
- `WeaponController`：主、副武器槽、快捷切换和短时近战扫掠；
- `StatusComponent`：状态添加、刷新、移除及免疫接口；
- `TalentCoreController`：永久内置天赋核心，管理等级、三套协议、各协议天赋、AI 接管待命和接管次数；
- `CircuitBreakerComponent`：独立管理黑匣中的断路保险、单局熔断状态和致命伤害拦截；
- `InteractionDetector`：E 键选择最近的统一交互对象；
- `VisualRoot`：身体、武器、突进残影、义体反馈、格挡和表现挂点；
- `Camera2D`：平滑跟随及鼠标方向前视。

## 2. 正式接口

外部系统应调用 `PlayerController`，不要依赖内部节点路径：

- `equip_weapon(data)`：替换当前目标武器槽；
- `equip_cyberware(item)` / `unequip_cyberware()`：装备或卸下单件/复合义体，并一次性刷新模块集合；
- `set_circuit_breaker_equipped(equipped)`：把断路保险移入或移出黑匣，不重置其已触发状态；
- `set_combat_protocol(id)`、`set_protocol_talent(...)`、`respec_protocol(...)`：协议终端配置入口；
- `refill_ai_takeover_charges()`：协议终端补充 AI 接管次数；
- `set_input_enabled(enabled)`：背包、暂停、结算和过场统一锁定输入；
- `repair(amount)` / `receive_damage(packet)`：耐久入口；
- `export_run_state()` / `import_run_state(state)`：跨楼层快照；
- `get_health_state()`、`get_heat_state()` 及各显示名查询：HUD 公共读取接口。

场景转发生命、热量、武器、突进、义体、格挡、交互、反馈和死亡信号。死亡只禁用玩家并发出 `player_died`，重载或结算由 `Main/RunManager` 决定。旧 `equip_mobility()` / `unequip_mobility()` 仅在迁移期兼容，不得再作为新系统入口。

## 3. 输入规则

| 输入 | 正式行为 |
|---|---|
| WASD | 八方向移动 |
| 鼠标 | 360° 瞄准；身体按瞄准方向选择上/下/侧动画 |
| 左键 | 当前武装的半自动、自动或蓄力触发语义 |
| 右键 | 每次点击执行一轮前摇、完美窗口、普通窗口和后摇 |
| Space | 固有突进；不依赖义体或其它装备 |
| E | 请求最近的统一交互对象 |

正式配置允许 Q/滚轮切换已携带的主、副武器。旧数字键移动模式切换只在迁移前调试构建中保留，v1.5 完成后删除。

## 4. 表现与占位素材

身体、武器、突进残影和义体反馈分层。武器挂点独立旋转，左半平面只翻转武器视觉；身体侧向动画使用右侧源图镜像。临时序列帧位于 `assets/art/characters/player/placeholder/`：

- 下、上各 4 帧，侧向 2 帧；
- 单帧约 20×30 px，帧间隔 1 px；
- 第一帧兼作待机，移动动画为 8 FPS；
- 攻击、格挡、受击和死亡暂用程序化反馈。

这些图片没有授权，只允许在私有开发仓库中占位。公开仓库或公开构建前必须替换并删除。

## 5. 伤害与行动状态

- 普通扣血后提供 0.18 秒受击保护；
- 普通受击不锁死操作，仅产生击退和反馈；
- 断路保险首次拦截致命伤害，将耐久锁为 1、清除状态并提供 1.2 秒无敌；
- 断路保险与天赋核心为两个独立组件，换装保险不会改变协议、天赋或接管次数；
- 保险已触发状态绑定实例，移出再装回不会刷新；旧版 `core` 快照仍可迁移到断路保险状态；
- 楼层快照继承耐久、武装、当前义体模块集合、天赋核心和断路保险状态；同一行动内继续下一层时保留义体，撤离、死亡或重新开局时清除；
- 玩家降到恰好 1 格耐久时，天赋核心进入接管待命；恢复到 2 格以上或死亡时取消待命，只有外部战斗逻辑确认接管行动成功后才消耗次数；
- 热量、格挡、击退、突进冷却、受击无敌和临时状态在新楼层重置；
- 楼层结算修复 1 格由流程层调用 `RunManager.capture_player_state(player, 1)` 完成。

## 6. 验收

自动测试现已检查 `DashController` / `CyberwareController` 节点契约、空义体槽、Space 固有突进、四模块兼容边界、断路保险单次触发且换装不刷新，以及协议、天赋和接管次数的独立持久化。专项物理检查另覆盖突进路径、无敌窗口、弹丸快照、持续射击与敌人脱锁。沙盒继续提供碰撞边界、1 格伤害板和近战训练目标，用于人工检查动画、瞄准、受击与扫掠命中。

玩家配置全局类名为 `CombatPlayerConfig`，避免与 Maaack 菜单插件的 `PlayerConfig` 重名。
