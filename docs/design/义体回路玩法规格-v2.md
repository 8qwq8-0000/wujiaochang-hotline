## 0. 启动器攻击与事件兼并裁定

- 初始三槽，喝人格饮料逐步扩到六槽；能量最终回复速度为每秒 40。
- 启动器在触发时锁定当前武器，从右侧依次执行回路；本轮结束后才发动攻击。武器决定攻击形态、伤害、散布与攻击间隔。普通按键开火只提交请求，本身不直接发弹。能量不足时请求丢弃，没有基础射击兜底；排队请求轮到执行仍不足时丢弃并退还开火冷却。
- 开火、突进、格挡、有效命中、击杀分别有事件启动器，统一使用“战斗突触感应器（事件）”命名和外观。突进开始、进入格挡状态各提交一次请求。有效命中只计直接造成的正伤害；玩家造成的爆炸、连锁、回声及持续伤害击杀均可提交击杀事件。同一条事件连锁中，同一种事件不重复触发。
- 不同事件启动器各自保留一个队列请求；同件复合启动器对同次事件只提交一轮。致命命中同时满足命中与击杀时，分开的义体各自触发；合成品只触发一次并带击杀标签。每件事件启动器每轮攻击最多提交一次命中请求和一次击杀请求。
- 锻造师可将不同事件监听兼并为一件，只占一槽，最多五种。已安装主体合成后就地替换。普通义体暂不合成。单件与复合品均为 12 能量、0.75 秒触发间隔。五种事件启动器的掉落总权重等于两件普通启动器，均分给尚未拥有的事件效果。
- 修正器只作用于本轮末尾的启动器攻击，不再产生跨轮待发射效果。追踪对弹丸、激光与剑气均生效；爆炸、连锁和回声对所有攻击形态生效。弹道接管弹独立，不享受本轮修正。
- 战术协处理器将当前攻击数翻倍，镜像也能翻倍，后续加成与复制作用于全部复制体。每轮最多 32 次攻击；超出时显示“武器过载”，跳过超额复制且不扣该槽能量。捕食性前庭环的每次重演独立结算攻击。灾厄之炎直接改写本轮末尾的攻击，不额外调用武器。
- 最终版本不使用热量，武器只受射速和攻击间隔约束。第一阶段仍保留旧热量作为过渡。掉落只受稀有度权重影响，不设楼层门槛。

## 1. 本版相对 v1 的实质变更

| # | 变更 | v1 | v2 |
|---|---|---|---|
| 1 | 能量结算 | 整轮预付，启动前一次性校验门槛 | 逐槽实时计算与扣除，无启动门槛 |
| 2 | 执行完整性 | 一旦启动，本轮必然完整执行 | 某槽扣不起即中止，直接跳轮末结算 |
| 3 | 热量系统 | 热量、冷却速率、热量上限、过热状态 | 整体删除，能量为唯一战斗资源 |
| 4 | 功能类别 | 只在总述出现，未落到任何一件义体 | 四分并设判定规则，写入 `CyberwareData` 字段 |
| 5 | 稀有度 | 散在 `ComponentRolls` 全局常量表 | 写入 `CyberwareData` 字段，全局表降为运行时缓存 |
| 6 | 标签结构 | `circuit_tags` 混装类标签、作用域、功能词 | `circuit_tags` 只留功能词，作用域改为 `target_scope` 受控词数组 |
| 7 | 动量回收肌腱 | 储存零热攻击充能（依赖热量） | 立即结束本轮回路并恢复 40 能量 |
| 8 | 轴突回收器 | 击杀后缩短其他义体剩余冷却（新体系无义体冷却） | 保留，改写为击杀启动时使本轮剩余槽能耗 ×50% |
| 9 | 热阈脉冲器 | 半径/时长在过热时翻倍 | 改名"冲击脉冲器"，纯化固定值 + 副本叠加 |
| 10 | 击杀热沉 | 降 12 热 + 回 12 能量 | 改名"击杀蓄能罐"，只回能量 |
| 11 | 义体总数 | 20 件 | 21 件（纳入轴突回收器） |

每一条都是不可逆决策，替代方案与当时的取舍待补 ADR（`docs/adr/` 尚未建立）。

## 2. 分类体系

### 2.1 两根正交轴

| 轴 | 字段 | 取值 | 决定什么 |
|---|---|---|---|
| 功能类别 | `circuit_kind` | 启动器 / 修正器 / 执行器 / 重构器 | 编译语义、HUD 类型色、编辑器分组与筛选 |
| 稀有度 | `grade` | 启动器 / 标准 / 军规 / 禁忌 | 算力价、楼层门槛、掉落权重 |

两根轴正交：`军规级修正器`、`标准级重构器` 都是合法组合。人格选择只改变天赋与人格能力，不限制义体类别（沿用 v1 §3.1）。

### 2.2 功能类别的判定规则

| 类别 | 判定 | 生效时机 |
|---|---|---|
| **启动器** | 只提交请求，不改变世界状态 | 提交时 |
| **修正器** | 挂起到未来某次玩家行为才兑现 | 执行期，写入容器 |
| **执行器** | 立即兑现一次动作或状态 | 执行期，当槽结算 |
| **重构器** | 改写本轮执行结构（顺序 / 间隔 / 终止 / 重演 / 调用方式） | 编译期，唯一在启动前展开的类 |

新义体归类时只回答两个问题：**它什么时候生效**（启动前 / 执行时 / 等未来行为），以及**它的产出有没有载体**。不需要回答"它属于攻击还是防御"——那是功能标签的事。

### 2.3 边界判据：编译期可得性

重构器与其余三类的唯一分界不是"作用对象"，而是**信息在启动前是否可得**。这条判据经过一次真实检验：

- 微转子反射束改"剩余槽间隔"→ 间隔在编译期即可算定 → **重构器**
- 轴突回收器改"剩余槽能耗"→ 能耗取决于本轮启动请求是否带击杀标签，编译期不可知 → **执行器**

两件都作用于"剩余槽"，却因信息可得性分属两类。此判据与 v1 §5.1「指令镜像、惯性反转和捕食性回绕由编译器在启动前显式展开」同源。

### 2.4 强化通道与条件分支

两者不同，不要混淆：

- **强化通道**：只有**副本叠加**一种。全系统没有"过热时翻倍""能量低于阈值时强化""敌人处于某状态时强化"这类成长方式。这是唯一成长手段。
- **条件分支**：同一件义体在不同触发下给不同数值，允许保留。例：击杀蓄能罐在启动请求含击杀标签时回 24 而非 12。

### 2.5 第三层：非轴的附加字段

- `target_scope`：受控词数组，描述"作用在谁身上"。它**不是分类轴**，不参与编辑器分组与筛选，只驱动执行规则与卡片显示。
- `circuit_tags`：纯功能词，供 UI 搜索与筛选。

## 3. 数据契约

### 3.1 `CyberwareData` 字段

```gdscript
enum CircuitKind {
	STARTER,        # 0 启动器
	MODIFIER,       # 1 修正器
	EXECUTOR,       # 2 执行器（v1 的 EFFECT / "生成器"）
	RESTRUCTURER,   # 3 重构器（v1 的 RULE / "规则件"）
}

enum Grade {
	STARTER,        # 0 启动器档
	STANDARD,       # 1 标准
	MILITARY,       # 2 军规
	FORBIDDEN,      # 3 禁忌
}

@export var circuit_kind := CircuitKind.STARTER
@export var grade := Grade.STANDARD
@export var target_scope: Array[StringName] = []
@export var circuit_tags: PackedStringArray = []   # 只允许功能词
```

枚举整数值不变，因此现有 `.tres` 的 `circuit_kind = 0/1/2/3` 无需重新映射，只改枚举标识符与显示名。

### 3.2 `target_scope` 受控词表

| 词 | 含义 |
|---|---|
| `pending_shot` | 挂到下一次玩家主动射击的待发射效果 |
| `weapon_call` | 直接调用当前武器 |
| `guard_call` | 调用一次赛博格挡 |
| `remaining_slots` | 改变本轮尚未执行的槽（间隔或能耗） |
| `whole_round` | 改变本轮整体（顺序、终止、重演）；捕食性前庭环还跨入下一轮 |
| `previous_slot` | 复制顺序上最近一枚义体的效果 |
| `none` | 直接作用于自身或敌人，无载体 |

多值合法（灾厄之炎 = `[pending_shot, weapon_call]`）。

### 3.3 唯一真相

类别与稀有度只存在于资源文件。`ComponentRolls.CYBERWARE_DROP_GRADES` 不再作为登记表，只允许作为运行时缓存或直接删除。新增义体只需新增一个 `.tres`，不得再要求同步修改任何全局表。

v1 的两处漂移是本条的由来：10 个 `.tres` 未声明 `circuit_kind`，而全局表多出了不在规格内的 `axon_recycler`。

## 5. 执行与能量模型

### 5.1 能量基线（沿用 v1 §3.2）

| 阶段 | 能量上限 |
|---|---:|
| 进入一层、饮料前 | 80 |
| 一层饮用后 | 100 |
| 二层饮用后 | 120 |
| 三层 / Boss 饮用后 | 140 |

- 基础回复 40/s，连续，无受击延迟
- 一层进场时当前能量等于当时上限
- 每次饮料扩容：上限 +20、当前能量 +20，不补齐原有缺口
- 跨区域、跨楼层保留当前能量，不自动回满
- 打开编辑器不改变能量

### 5.2 启动检查

提交请求时只校验一项：**当前能量是否足够支付该启动器的耗能**。

- 足够：扣除启动器耗能，进入第一槽
- 不足：**丢弃请求**，不扣能、不入队、不空转，HUD 短暂提示"能量不足"。定时启动器在下一拍自然重试。

不存在"启动门槛"概念。v1 §3.3 的净耗能公式 `启动门槛 = 启动器耗能 + 所有指令耗能 - 固定回能` 整条删除。

### 5.3 逐槽实时扣能

每槽执行前校验该槽当前能耗（可能被轴突回收器打折）：

- 足够：扣除，执行该槽
- 不足：**立即中止**

单步间隔默认 0.05 s，任何加速后的下限 0.01 s。

### 5.4 中止

"中止"= 直接跳到本轮结束结算。与主动跳转（动量回收肌腱）走**同一条结算路径**，区别只在触发者：

- 已预付不存在，故无退还问题
- 已产生的待发射效果照常在本轮结束合成
- 已发生事件照常入队
- 捕食性前庭环的轮后重演照常可发生
- 灾厄之炎的"轮末无武器调用则自行调用一次"仍按轮末触发

中止与过热无关——过热概念已删除（见第 7 章）。除能量不足外，没有任何条件能中止本轮。

### 5.5 跳转

动量回收肌腱执行时立即跳轮末。它排在越前面，剩余槽的收益越无法兑现，因此"把回能件排在重活之前"成为一条真实排序策略。若排在首槽，本轮只执行它一件。

### 5.6 请求队列

v1 §4.2 的五个理由瘦身为三个：

- 同时只有一轮活动回路
- 主动、事件、定时三类各最多保留 1 个待处理请求；同类新请求覆盖该类旧请求的目标与标签，不无限排队
- 优先级：主动 > 事件 > 定时

已删除的理由：能量不足等待、启动时武器过热等待。两者统一为"丢弃请求"。

死亡、新行动、无效切场景清空队列（沿用 v1）。

### 5.7 快照

启动成功时快照：槽位排列与持有副本、当前武器及参数、当前人格/天赋/事件标签/可用储能、编译后的真实执行顺序。

**不再快照"预付结果"**（该概念已不存在）。执行期打开编辑器暂停全图，旧轮仍使用原快照，新排列从下一轮生效，编辑不恢复能量、不重置间隔（沿用 v1 §2.3）。

### 5.8 预测量

虽然不再有门槛，编译期仍可逐槽模拟出两个预测值，供编辑器与 HUD 显示：

- **预计净耗能**：按真实展开顺序累加各槽能耗与固定回能
- **预计中止槽**：从当前能量出发，第一个扣不起的槽位

两者都是预测，不是准入条件。中途条件回能（击杀、完美格挡）不计入预测。

- 不追溯修改已生成的弹丸或已执行效果

## 14. 既有义体的信号迭代裁定（2026-11-06）

本章覆盖前文冲突的既有义体规则。新增义体构思留待后续版本，本轮实施范围不增加义体 ID。

- 启动器锁定当前武器并生成一组待发射攻击；散弹的每颗弹丸、激光束、刀气与近战挥击各算一条攻击轨迹。回路从触发启动器右侧走完一圈，途中其他启动器免费空过。不同启动器的请求依次执行，各有独立信号。
- 同一信号从左到右经过槽位。修正器只修改到达时已有的攻击；义体即时效果读取到达该槽时的攻击条数；轮末才生成战场攻击。每轮最多 32 条实际攻击轨迹，某槽的变换若会超额，该槽空过且不扣能并提示“武器过载”。
- 战术协处理器 18 能量，按原方向复制当前所有攻击，副本和原攻击共同经过右侧义体，不改变弹道。
- 智能火控 8 能量：弹丸与刀气追踪，激光与近战只在发射前校准方向。爆炸弹匣 14 能量：每次齐射首次有效命中爆炸一次，复制出的齐射各有一次机会。电弧弹道皮层 22 能量：各攻击独立连锁，连锁不递归。轨迹回响处理器 28 能量：回响继承最终攻击效果，不能再生成回响，间接伤害不能作为回响起点。
- 光学入侵器按信号到达时的攻击条数延长脱锁时间；冲击脉冲器按条数扩大玩家周围的失衡范围。副本叠加仍独立生效。弹道接管协议按该条数扩大搜索范围，不设数值上限；没有可接管敌弹时不生成基础弹。
- 击杀蓄能罐花费 10，执行时回能 20；击杀事件启动时回能 30。轴突回收器花费 18，无条件使后续槽位能耗减半。微转子反射束花费 10，使后续执行间隔乘 0.25，下限 0.01 秒。动能回收腱花费 12，回能 40 并立即结算已形成的攻击信号。
