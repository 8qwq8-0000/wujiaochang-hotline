# 《五角场热线》素材制作基线

> 版本：v1.4（冻结基线）<br>
> 生效日期：2026 年 10 月 14 日<br>
> 适用项目：五角场热线<br>
> 小组：希腊奶<br>
> 引擎基线：Godot 4.7.2 Stable / GL Compatibility<br>
> 状态：已确认；后续变更必须留痕

本文档将项目准备清单与团队逐项确认的决定整理为可执行标准。它约束正式美术、UI、字体、音效、音乐、特效及其源文件，也规定 AI 草稿和第三方素材如何进入项目。

如本文档与早期准备清单中的旧规则冲突，以本文档为准。原始策划方向不变，但尺寸、调色板、灯光、AI 工作流等细节采用本次冻结后的规则。

---

## 1. 基本原则

1. 正式素材进入主分支前必须符合本基线。
2. 原型阶段允许临时素材偏离标准，但必须使用 `placeholder_` 前缀，并登记来源、替换负责人和计划替换时间。
3. 占位素材不得进入公开构建。
4. 游戏信息不能只依赖颜色传达；敌我、交互和危险还必须使用轮廓、图标、闪烁节奏或方向提示。
5. 碰撞、攻击判定、脚底锚点和表现素材互相独立，禁止通过放大碰撞框迁就画面。
6. 文件和目录使用小写 `snake_case` 英文命名，不使用中文、空格或含义不明的编号。

---

## 2. 显示与像素网格

### 2.1 逻辑分辨率

- 游戏内部画布固定为 **640×360、16:9**。
- 默认窗口为 1280×720。
- 优先使用整数倍缩放和最近邻采样。
- 非 16:9 屏幕使用黑边，不拉伸画面，也不扩大战斗视野。
- 窗口小于逻辑画布时可以使用非整数缩放，但 UI 仍须尽量对齐整数坐标。

### 2.2 基础尺寸

| 类型 | 基线尺寸 | 说明 |
|---|---:|---|
| 地图瓦片 | 32×32 px | 常规逻辑网格 |
| 普通角色单帧 | 32×32 或 64×64 px | 小型/简化角色优先 32×32，主角等需要更清楚轮廓与肢体负空间时允许 64×64；脚底锚点分别建议为 `(16, 28)`、`(32, 57)` |
| 大型敌怪/突进残影 | 64×64 px | 可按需要扩大，但中心与脚底基准必须稳定 |
| 近战武器 | 32×16 px | 武器与身体分层 |
| 手枪类武器 | 24×12 px | 武器与身体分层 |
| 背包图标 | 32×32 px | 保持清晰轮廓 |
| 背包展示 | 48×48 px | 可由原图整数缩放 |
| 普通命中特效 | 16×16 px | 建议 3～4 帧 |
| 完美格挡特效 | 64×64 px | 建议 4～6 帧 |

32×32 是普通素材的起始基线，不是角色尺寸上限。主角或结构复杂的普通单位在 32×32 下出现轮廓黏连时，可以改用 64×64；增加画布应优先服务于清晰边缘、肢体负空间和稳定锚点，不能借机堆叠微小装甲缝、划痕或不可读符号。大体型素材也可以使用 64×64 或更大网格，但不得随意采用非网格尺寸造成锚点漂移和拼装困难。

### 2.3 图像格式与导入

- 正式位图使用 RGBA、sRGB、透明背景 PNG。
- 像素主体素材关闭抗锯齿、模糊、纹理过滤和 Mipmap。
- 角色、场景瓦片、武器、图标和逐帧特效采用最近邻采样。
- 灯光渐变、光晕遮罩、法线贴图和少数 Shader 辅助纹理允许线性过滤，但不得承担像素主体轮廓。
- 像素主体与灯光辅助纹理使用不同的 Godot 导入预设。

## 3. 调色板与可读性

### 3.1 调色板

- 全项目维护约 **32 色核心调色板**。
- 玩家识别色为青/蓝；敌人为红/橙；可交互物为黄；环境以低饱和灰色为主。
- 每个区域最多增加约 8 个主题色，用于区域气氛和地标差异。
- 普通 32×32 素材建议控制在 16～24 色，而不是硬性限制为 16 色。
- VFX、灯光、透明渐变和 UI 不受单素材色数限制，但必须保持阵营色语义稳定。
- 禁止成员各自创建几乎相同的近似颜色；常用新增颜色必须回收到共享调色板。

### 3.2 非颜色识别层

- 玩家、敌人、可交互物和危险提示必须至少具有一种非颜色识别方式。
- 推荐组合：颜色 + 轮廓形状、颜色 + 图标、颜色 + 闪烁节奏、颜色 + 方向标记。
- 降低饱和度后仍应能够判断敌我、危险和交互对象。

## 4. 角色、武器与义体

### 4.1 动画方向与帧率

- 动画帧横向排列。
- 玩家固定制作下、上、左、右四组方向；左、右方向使用不同序列帧，不通过运行时镜像互相替代。
- 玩家允许使用左右不对称的基础身体、义体、灯带和挂载结构；各方向必须保持结构连续，不能在转向时交换部件所在侧。
- 左右对称的常规敌人和 NPC 可以只制作下、上、侧面三组方向，并通过镜像复用左右方向；侧面源图朝向须在同类素材中保持一致。
- 带文字、明显单侧装备或其它不允许镜像结构的敌人和 NPC，必须单独制作左、右方向。
- Boss 在左右不对称会影响识别或动作时制作完整四方向。
- 起始动画速率：待机 4 FPS、移动 8 FPS、攻击/受击 10～12 FPS。

### 4.2 分层规则

- 玩家身体、武器、义体反馈和突进残影分层制作，不为每种组合重画完整角色。
- 武器与枪口焰可以独立 360° 旋转；身体继续使用离散方向动画。
- 固有突进复用基础身体当前帧，通过池化残影、速度线和短时轮廓故障表达，不制作轮式、四足或悬浮底盘。
- 义体不替换玩家移动循环；单件与复合义体共用身体素材，只通过 HUD 子图标、局部灯带和效果特效区分。
- 所有单位以脚底锚点参与 Y 排序。
- 武器根据朝向切换到身体前方或后方；头顶 UI、完美格挡提示和关键警告不参与场景遮挡。

#### 主角腕锁式武器挂载

- 主角采用腕锁式“伪握持”，不要求人物序列帧逐帧画出握把或扣扳机动作。
- 每个方向、每个动画帧维护独立右腕坐标；`WristSocket` 按当前动画与帧号跟随右腕。
- 固定接口套筒覆盖右腕和部分手掌，武器以套筒内的万向关节为轴独立 360° 瞄准；AI 负责稳定枪身。
- 警棍、手枪和散射器复用相同快拆接口。散射器必须包含向腕后延伸的缓冲托架，以解释单臂后坐力。
- 向下、向右时枪身位于人物前方；向上、向左时枪身位于人物后方。固定套筒始终覆盖腕部。
- 人物 PNG、原有手掌姿态和六帧步态保持不变；腕点偏差通过坐标表修正，不通过重画整套动作解决。

### 4.3 固有突进与义体表现范围

- 固有突进：当前身体帧残影、短促速度线、撞击火花和冷却提示；四方向锚点必须与步行一致。
- 智能火控：目标锁定标记、弹丸追踪微光和有限转向轨迹，不长期覆盖屏幕。
- 爆裂弹仓：小型圆形冲击波和范围命中火花，与燃料桶等环境大爆炸保持尺寸差异。
- 战术协处理器：HUD 连续击发状态与过热恢复后续射提示，不额外重画武器动作。
- 光学入侵器：突进期间玩家轮廓产生青蓝监控故障，敌人头顶显示短促失锁符号；不能与受伤闪烁混淆。
- 复合义体：装备图标使用四个固定子图标显示已集成模块，不为十五种组合制作独立外观。

## 5. 场景模块与灯光

### 5.1 模块化比例

- 不同区域共用约 70% 的墙体、地面、门框、管线、护栏和碰撞结构。
- 约 30% 用于区域招牌、配色、地标和装饰差异。
- 房间结构、碰撞和装饰分层，避免美术替换破坏关卡逻辑。

### 5.2 中性素材与动态灯光

- 场景和角色素材使用中性/局部固有色，不烘焙固定方向光。
- 接触阴影和必要的材质明暗可以保留，但不得假定整张图统一受某个方向照射。
- 环境底色由 `CanvasModulate` 控制。
- 灯具、霓虹、枪口焰、警报和完美格挡使用 `PointLight2D` 或相应短时灯光。
- 场景设计者手工放置静态灯光与 `LightOccluder2D`；运行时管理器负责环境色、区域色调、性能档位和开关。
- 临时战斗灯光必须进入对象池，不在战斗过程中反复无上限实例化。
- 发光贴图不会自动生成灯光节点；灯光必须显式配置。

### 5.3 灯光预算

- 同屏静态灯光最多 12 个。
- 同屏投射阴影的灯光最多 4 个。
- 同屏临时战斗灯光最多 8 个，默认不投射阴影。
- 超出预算的远景霓虹只保留发光核心和光晕，不创建 `PointLight2D`。
- 场景切换时释放旧场景灯光；池满时优先回收最旧、最远或最低优先级灯光。
- 最低配置以团队中性能最低的电脑稳定 60 FPS 为验收线。

### 5.4 法线贴图

- 首阶段只为关键墙面、Boss和大型机械制作法线贴图。
- 先由高度图工具生成，再人工修正轮廓和凹凸方向。
- 普通地砖、小道具和常规角色默认不制作法线贴图。

## 6. 赛博朋克霓虹与招牌

- 霓虹由清晰的像素发光核心、受控光晕、局部灯光溢出和简化反射组成。
- 像素主体边缘必须保持硬朗；光晕可以平滑，但在 640×360 逻辑画布上生成并随画面整数缩放。
- 禁止用高分辨率大面积模糊代替像素结构。
- 普通阴影保持偏硬；大型招牌、Boss和完美格挡可以使用更宽的光晕。
- 提供降低光晕强度的画面设置。
- 招牌文字、发光核心、光晕和反射分别放在独立图层。
- 最终中文招牌由人工排字或重绘；AI 不负责最终文字正确性。
- 招牌、商铺和品牌均为虚构，不复刻现实商标。
- 关键玩法文字通过 UI 显示，不依赖环境招牌传达。

环境、地面和道具可以被整体压暗；玩家与敌人可以受场景灯光影响，但必须保留不受环境暗度吞没的阵营色轮廓。预警、交互提示、准星、完美格挡提示和 HUD 始终保持可读。隐身只有在明确作为玩法机制时才允许打破此规则。

## 7. UI 与字体

- UI 面板、图标和边框遵循像素网格与整数坐标。
- 不手绘完整中文字库。
- 正文使用许可清晰、尺寸适合的现成中文字体，并锁定字号和整数位置。
- 标题、伤害数字和少量关键提示可以使用像素字体或定制字形。
- 字体目录名称不能替代许可证核验；`个人非商` 与 `未知` 字体不得进入公开构建。
- 所有正式字体必须在 `docs/legal/素材来源与许可.md` 中登记来源、许可证和使用范围。
- 战斗 HUD、背包、暂停、设置与撤离界面的具体样式遵循 `docs/design/赛博朋克UI视觉基线.md`。

## 8. 特效制作

### 8.1 制作方式

- 命中火花、完美格挡、关键攻击轮廓等核心反馈使用短逐帧像素动画。
- 尾迹、光晕、扬尘、雨滴和短时灯光优先使用 `GPUParticles2D`、`CPUParticles2D`、`Line2D`、Shader和灯光池生成。
- 所有运行时战斗特效统一接入项目现有 `VFXManager`，不再并行引入第二套全局 VFX 管理器。
- 新效果必须遵守总量预算、预热和回收机制。

### 8.2 GitHub 参考组合

- 粒子基础参考 Godot 官方 `godot-demo-projects/2d/particles`。
- 战斗效果参考 `haowg/GODOT-VFX-LIBRARY`，只选择性移植脚本、场景参数和 Shader。
- 拖尾参考 `Gabbinetto/Trail2D-addon`，改写成项目自有节点，不保留运行时插件依赖。
- `Brackeys/brackeys-particle-controls` 仅可作为编辑器预览辅助。
- 不引入上述仓库中的示例美术、纹理或音频。
- 不使用抗锯齿 Line2D 插件处理像素主体拖尾。

## 9. 音频标准

### 9.1 音效

- 短音效使用 44.1 kHz、16-bit、mono WAV。
- 峰值不高于 -3 dB。
- 删除无意义的开头静音和过长尾响。
- 武器、脚步、敌怪、机关和环境声使用 `AudioStreamPlayer2D`，具有空间定位和距离衰减。
- UI、完美格挡确认音、受击警报等关键反馈使用非空间音频。
- 高频重复音效准备 2～4 个轻微变化，并限制同类声音并发。

### 9.2 音乐与环境循环

- 音乐与长环境声使用 44.1 kHz、stereo OGG。
- 峰值不高于 -6 dB。
- 循环素材必须检查首尾衔接，避免爆点、空白和明显音量跳变。

## 10. AI 与第三方素材

### 10.1 AI 图像

- AI 图像既可以用于构图、气氛、配色和造型方向草稿，也可以作为正式素材候选，但生成结果不得未经人工验收直接进入运行目录或公开构建。
- 正式候选必须由成员完成技术、视觉与版权验收；通过验收后可以直接使用，不再强制完整人工重绘。未通过的局部必须在 Aseprite 等工具中按网格修正、重绘或替换。
- 像素素材的人工技术验收至少包括：画布尺寸、透明通道与边缘、像素网格、调色板、锚点、分层关系、最近邻采样、纹理过滤与 Mipmap 设置。
- 人工视觉验收至少包括：正常游戏缩放下的轮廓与负空间、暗场可读性、阵营与危险语义、动画或阶段切换时的结构连续性，以及是否存在多余肢体、错误文字、破碎透视和生成伪影。
- 人工版权验收至少包括：生成工具与服务条款、提示词和输入参考来源记录、商标与受保护角色风险、项目公开发布和商用范围兼容性。
- 不提示模仿具体艺术家、现有游戏、商标或受版权保护角色。
- 记录生成工具、日期、提示词、输入参考、验收人、验收结论、编辑者和人工修改内容。
- AI 原图和提示词归入 `art_sources/ai_drafts/`；人工生产源文件归入 `art_sources/production/`；运行目录只保留通过验收的导出文件。
- 只提交被实际采用的 AI 参考图、正式候选源图和生成记录；废稿放团队共享备份，不进入 Git 仓库。

### 10.2 AI 音频

- AI 音频可以作为声音方向草稿，不能未经处理直接作为正式素材。
- 正式使用前必须完成剪辑、去静音、峰值控制、循环与噪声检查。
- 必须记录生成工具、日期、提示词和许可条件。
- 来源或商用权限不明确的音频不得进入正式构建。

### 10.3 第三方素材

任何第三方素材必须在使用前登记：

- 原始名称与来源链接；
- 作者；
- 许可证；
- 下载日期；
- 修改内容；
- 负责人；
- 项目内最终路径；
- 是否允许公开发布和商用。

许可证未知、仅限个人使用、禁止改作或与项目发布方式不兼容的素材，不得进入公开构建。

## 11. 源文件与版本控制

- 像素素材同时保留 `.aseprite` 源文件和导出的 PNG。
- 每个源文件指定一名主要负责人，避免多人同时编辑二进制文件。
- 大型源文件另行备份；仓库内单文件控制在 20 MB 以下。
- 当前不启用 Git LFS。
- 运行时目录中不得混入废稿、未采用方案和无许可文件。

---

## 12. 验收与自动检查

### 12.1 自动检查项

- 文件名和路径是否符合 `snake_case`；
- PNG 尺寸、透明通道和基础格式；
- Godot 纹理过滤与 Mipmap 配置；
- 音频格式、采样率、声道和峰值；
- 占位素材是否使用 `placeholder_` 前缀；
- 必需的来源记录是否存在。

自动工具只报告问题，不擅自修改源文件。

### 12.2 人工复核项

- 脚底锚点、Y 排序和动画抖动；
- 轮廓、阵营和危险提示可读性；
- 调色板是否失控；
- 灯光分层和暗场表现；
- UI 与中文字体清晰度；
- 音效反馈、循环接缝和混音层次；
- 第三方与 AI 来源、许可证及修改记录。

### 12.3 合并规则

- 正式素材未通过检查不得合并到主分支。
- 开发急需但尚未达标的素材只能以占位状态合并。
- 影响碰撞、可读性或正式发布的问题必须返工；纯装饰细节可排入后续迭代。

## 13. 基线变更流程

本标准自 2026 年 10 月 14 日起冻结。后续允许修改，但每次修改必须记录：

1. 修改原因；
2. 影响范围；
3. 旧素材是否需要返工；
4. 负责人；
5. 生效日期。

已开工素材不因小型调整自动全部返工；只有影响碰撞、玩法可读性、许可证或公开发布时，才要求立即统一更新。
