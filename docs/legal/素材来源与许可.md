## 0. 使用说明

1. **每引入一个第三方资源（代码 / 美术 / 音频 / 字体），必须在下表新增一行。**
2. 许可证一律写 **SPDX 标识符**（如 `MIT`、`OFL-1.1`、`CC0-1.0`），**不要只写「免费」**。
3. 代码/插件必须登记 **commit hash 或 tag**——仓库会变、许可证也会变。
4. 来源 URL 指向**素材详情页**，不要写 CDN 直链（会失效）。
5. **「未能确认来源的素材」一节必须在公开发布前清零。**

### 4.4 已核实与项目相关的 OFL 条款

若改用 Noto Sans SC / Source Han Sans（OFL-1.1）作为备选，义务相同：

- ✅ **打包进游戏不会让游戏变成 OFL。** FAQ 1.3：*"Only the portions based on the Font Software are required to be released under the OFL. The intent of the license is to allow aggregation or bundling with software under restricted licensing as well."*
- ✅ **可以卖含 OFL 字体的游戏**（FAQ 1.4 明确列出 games and entertainment software）。
- ✅ **不需要为「使用」字体而署名。** FAQ 1.1.2：*"No. Font authors may appreciate being mentioned … but that is not required."*
  → 与网上常见的「OFL 必须署名」说法相反。**我们仍会在 credits 里致谢，但那是礼貌，不是义务。**
- ✅ 打包/内嵌时可不必附完整 OFL 文本（FAQ 1.10）；FAQ 1.20 建议**至少**在 About 框给出「版权声明 + 许可声明 + 许可文本」。

**两个必须遵守的：**

- ⚠️ **不得只出售字体本身**（FAQ 1.6）。
- ⚠️ **Reserved Font Name 条款（5.2 / 5.9）：修改后的字体不得继续使用原字体名（如 "Ark Pixel" / "Noto" / "Source"）。**
  → 如果我们对点阵字体做子集化/字形裁剪/改尺寸，**必须改名**并在内部名称字段同步修改。

## 5. 字段填写规范

| 字段 | 要求 |
|---|---|
| 名称 | 资源原名，不要自创译名 |
| 作者/组织 | 个人或组织名；GitHub 用 `owner` |
| 许可证 | **SPDX 标识符**：`MIT` / `Apache-2.0` / `BSD-2-Clause` / `MPL-2.0` / `LGPL-3.0-or-later` / `GPL-3.0-only` / `AGPL-3.0-only` / `CC0-1.0` / `CC-BY-4.0` / `CC-BY-SA-4.0` / `OFL-1.1` |
| 来源 URL | **素材详情页**，不是 CDN 直链（CC-BY 要求的是「指向素材的 URI」） |
| 引用版本 | 代码/插件必填 **commit hash 或 tag**；素材填版本号 |
| 获取日期 | `YYYY-MM-DD`——审计链关键，证明当时取的是哪个版本 |
| 使用位置 | 工程内路径或用途 |
| 是否修改 | 修改过就必须能说明改了什么（Apache-2.0 与 CC-BY 都要求标注改动） |
| 署名要求 | 该许可证是否要求署名、放在哪里 |

## 6. 许可证义务速查

| 许可证 | 必须做的 | 对本项目的含义 |
|---|---|---|
| `MIT` | 保留版权声明 + 许可文本 | 推荐库的绝大多数，保留出处即可 |
| `Apache-2.0` | 版权/许可通知 **＋ 标注改动 ＋ 有 NOTICE 要一并携带** | 比 MIT 多两件事 |
| `BSD-2-Clause` | 版权/许可；**二进制分发时**须在「文档和/或其他材料」中重现声明 | 我们导出 `.exe` → **必须放随包文档/关于页** |
| `MPL-2.0` | 单文件级 copyleft | 改过的 `addons/` 内文件要开源，游戏主体不受影响 |
| `CC0-1.0` | **无任何义务** | Kenney 素材；仍建议登记 |
| `CC-BY-4.0` | 署名 + 版权 + 许可 + 免责声明 + **素材 URI**；改动需标注 | 要求比想象中多 |
| `CC-BY-SA-4.0` | CC-BY 全部 ＋ 改编后同许可 | ⚠️ 建议原样使用不改编 |
| `OFL-1.1` | 见 §4 | 字体首选 |
| `GPL-3.0` / `AGPL-3.0` | Disclose source + Same license + State changes | ⛔ **禁止引入**，见下 |

### GPL 与 `addons/` 子目录（必读）

常见说法「GPL 插件放在 `addons/` 里就算独立作品，不传染我的游戏」**站不住**：

GPL-3.0 §5(c) 原文：*"You must license the entire work, as a whole, under this License … regardless of how they are packaged."*

诚实标注：§5 标题是 *"Conveying **Modified** Source Versions"*，真正的判定标准是「衍生作品 / 基于」的界定，而 GPL 正文未像 LGPL 那样给出清晰的接口界线 → **原封不动的 GPL 插件与专有游戏一起分发属法律灰区**。

**本项目规则：**

- ⛔ 不引入任何 `GPL-*` / `AGPL-*` 资源（含 AGPL-3.0 的 `xlljc/GunfireDungeon`）
- ⚠️ 引入任何资源前，**读仓库根的 `LICENSE` 本体，不要信 README 自述**
  - 真实案例：`bitwes/Gut` 的 GitHub API `license` 字段是 `null`，但 `LICENSE.md` 实际是 MIT
  - 反向案例也存在（README 写 MIT、LICENSE 写 GPL）
- ⚠️ Asset Library 有两个名字几乎相同的存档资产：**4305「Addon Save (4.x)」= MIT**，**2326「Addonsave (4.1)」= GPLv3**——**拉错就传染**
