# Godot 4 存档系统开源方案调研（面向学生团队 7 周项目）

> 调研时间：2026-10（以 GitHub API / 仓库 raw README / Godot Asset Library 页面为准）
> 项目：上帝视角双摇杆 Roguelite（带撤离），Windows PC，Godot 4.x（4.7 或最新稳定版）
> 所有 star / 许可证 / 日期均为实测值；无法核实的一律标注「未验证」。

## 0. 一句话结论

**首选 `youssof20/savestate`（SaveState Lite 2.0）作为存储层**：它是本次调研中唯一同时原生具备「schema 迁移 + 原子写（.tmp→commit）+ 备份世代 + 多槽位 + 自动保存 + 设备设置与档案进度分离」的 Godot 4 插件，且作者明确在 Windows 上测过 Godot **4.5.2 / 4.6.3 / 4.7.2**，与你们的引擎版本完全对齐。
**次选 `locker-godot/locker`**（60★，MIT，内置存档版本化 + 加密策略 + 分区 + 异步）。
**若团队不想引入第三方依赖，自研 ~200 行 SaveManager 完全可行且风险最低**，用本报告第 4 节给出的官方 API 组合即可。

## 2. 重点候选详情（含本项目集成建议）

### 2.1 `youssof20/savestate`（SaveState Lite 2.0）— 最贴合需求

- 仓库：https://github.com/youssof20/savestate
- Asset Library：https://godotengine.org/asset-library/asset/4990 （条目为 **1.0.0**，MIT，Tools 4.3，提交于 2026-04-05）
- 许可证：**MIT**（含 `LICENSE`，README 要求保留声明）
- 版本：`addons/savestate/plugin.cfg` → `name="SaveState (Lite)"`, `version="2.0.0"`, `script="plugin.gd"`
- 兼容：README 明确「Windows tested with Godot **4.5.2, 4.6.3, 4.7.2**」→ 与你们的 4.7 目标一致
- 规模：18★ / 1 open issue / 0 fork / 创建 2026-04-02 / 最后 push 2026-09-24（活跃）
- 形态：**标准 addon**（copy `addons/savestate` 即可），自带编辑器 Dock 浏览存档

核心 API（来自 GUIDE.md 实测文本）：
```gdscript
SaveManager.start_session()                      # 必须在用会话 API 前调用
SaveManager.set_value(&"coins", 25)              # 写
SaveManager.get_value(&"coins", 0)               # 读（带默认值）
SaveManager.register_key(key, type, default)     # 声明键的类型与默认值
await SaveManager.save_game(&"before_boss")      # 命名检查点
SaveManager.load_game(&"before_boss")            # 允许回滚/丢弃未保存
SaveManager.new_playthrough(name, initial_data)  # 新建独立存档
SaveManager.list_slots() / rename_slot / duplicate_slot / delete_slot
SaveManager.list_slot_history() / recover_slot(slot, generation_id)
SaveManager.get_profile_data() / set_profile_data(data)   # 跨存档共享的进度
SaveManager.get_device_data()  / set_device_data(data)    # 与存档无关的设置
SaveManager.mark_dirty()                                  # 触发自动保存
```
- 自动保存：`mark_dirty()` 标记脏数据；`auto_save_debounce_sec`（静默间隔）、`auto_save_max_interval_sec`（连续修改时的上限）；信号 `operation_finished` / `autosave_paused`
- 节点属性持久化：给节点加 **SaveComponent** 子节点，设置唯一 `storage_key` 与 `tracked_properties`
- **Schema 迁移**（本项目的硬需求）：
```gdscript
extends RefCounted
func configure(manager: SaveManagerBase) -> void:
    manager.set_schema_migrations([upgrade_1_to_2])
func upgrade_1_to_2(data: Dictionary) -> bool:
    data["inventory"] = data.get("inventory", [])
    return true
```
  再设置项目设置 `savestate/schema_setup_script` 与该脚本，`savestate/current_version = 2`，重启项目。迁移回调按索引 0 → 1→2、索引 1 → 2→3。
- 失败处理：**校验失败会报告错误而不会替换已接受的状态**（正好对应你们「读失败保留旧文件并新建」的要求）；`SaveStateResult.ok / status / message / data_path`
- 多槽：目录上限 128；`generation_retention` 默认保留 5 代（最少 2）；「保留世代可帮助从写入中断中恢复，但不保证断电或并发写入」
- 路径：项目设置 `savestate/save_root`，默认 `user://savestate`
- Lite 限制：**同步写**、Dock 只读、单 profile、明文无加密；Pro（付费，https://chuumberry.itch.io/savestate-pro ）才有异步写、AES 加密、缩略图、可视化编辑、多 profile

本项目集成建议：
1. `addons/savestate/` 复制进来 → Project Settings → Plugins 启用 → 自动注册 `SaveManager` autoload
2. 自己再写一个薄封装 autoload（如 `GameData.gd`）承载领域模型，避免游戏逻辑到处直接调 `SaveManager`：
   - `warehouse`：`Array[Dictionary]`，每项 `{uid:String, quality:int, affixes:[{id:String, value:float}], ...}`，用 `set_value("warehouse", arr)` 整体写入（Lite 要求「有界的字典/数组与受支持的原生值」，正好匹配）
   - 永久解锁：`set_profile_data({rescued_npcs:[...], unlocked_drops:[...]})`
   - 教程标记：`set_value("tutorial_flags", {...})`
   - 设置：`set_device_data({volume:..., resolution:..., keybinds:{...}})`（与存档解耦，符合「设备级设置」语义）
   - 最佳纪录：`set_value("records", {...})`
   - schema 版本：`savestate/current_version` + `savestate/schema_setup_script`
3. 自动保存触发点：在撤离成功 / 合成完成 / 仓库整理 / NPC 获救 / 解锁 / 设置变更之后各调一次 `SaveManager.mark_dirty()`，交由去抖定时器真正落盘；**局内不做中途存档**正好符合 Lite「按检查点」的模型
4. 多存档位：`new_playthrough()` + `list_slots()` 即得（可选，非必需）

坑：
- 插件很年轻（2026-04 创建，18★），**API 在 1.0 → 2.0 之间发生过不兼容变化**（1.0 是 `SaveManager.save_slot(0)`，2.0 变成 `start_session()` + `save_game(slot)`）→ **务必锁定 2.0.0 并把 addon 目录一并提交进版本库**，不要依赖 Asset Library 的 1.0.0 条目
- 只有 3 个 Windows 版本做过认证测试，Lite 是同步写（存档小、24 格仓库没问题）
- Lite/Pro 功能切分明确：加密、异步写属 Pro，评估时不要把 Pro 特性算成免费

### 2.2 `locker-godot/locker` — 最「正统」的框架式方案

- 仓库：https://github.com/locker-godot/locker ｜ Asset Library：https://godotengine.org/asset-library/asset/3765 （**1.1.2**，MIT，Tools **4.3**，2025-04-26）
- 许可证：`LICENSE` 实测文本为 **MIT**（并因使用 Material Design Icons 附 **Apache-2.0** 段落）→ 两者皆为宽松许可，课程项目可发布
- 规模：60★ / 4 open issues / 最后 push 2026-05-26；`plugin.cfg` → `name="Locker"`, `version="1.1.2"`, `script="locker.gd"`（仓库 master 比商店 1.1.2 更新）
- 形态：标准 addon，启用后自动注册 autoload **`GlobalStorageManager`**

核心概念与 API（README 实测）：
- `StorageAccessor`（Node）：负责某个数据集的存取与版本；`StorageManager`：管理一组 accessor
- `AccessStrategy` 抽象读写方式，内置 **`JSONAccessStrategy`** 与 **`EncryptedAccessStrategy`**
- 多存档文件 + **分区（partitions）**（可按玩家/用途切分，减少加载量）
- 异步：API 为协程，可 `await`，并提供开始/结束信号
- **存档版本化**：`StorageAccessorVersions` 允许为不同存档版本定义不同数据结构处理方式
- 配置全部位于 ProjectSettings 的 `addons/locker` 路径下；含 GUT 单元测试；文档写在代码 doc comment 里

本项目集成建议：适合「一个 accessor 管 warehouse、一个管 progression、一个管 settings」的切分；加密开箱即用；版本化能覆盖你们的 schema 需求。代价是先理解 `StorageAccessor/StorageManager/AccessStrategy` 三层抽象，约需 1 天。

坑：Asset Library 稳定版停在 2025-04 的 1.1.2，仓库 master 有更新（2026-05）→ 想用新特性得走 GitHub；原子写与备份策略在 README 中**未文档化**（未验证），关键需求要自己读代码确认或自行加 `.tmp` 包装。

### 2.3 `AdamKormos/SaveMadeEasy` — star 最多、但已停滞

- 仓库：https://github.com/AdamKormos/SaveMadeEasy ｜ Asset Library：https://godotengine.org/asset-library/asset/2056 （**1.3**，MIT，Tools 4.1，2024-06-06）
- 许可证：**MIT** ｜ 规模：**220★** / 4 open issues / 最后 push **2025-01-01**（以 2026-10 计已近 2 年无提交，**基本停滞**）
- `addons/save_system/plugin.cfg` → `name="SaveSystem"`, `version="1.3"`, `script="plugin_save_system.gd"`
- 形态：addon；README 要求把 SaveSystem autoload **放到 autoload 顺序第一位**

API（README 实测）：
```gdscript
set_var("Bob:a:b", 3)      # 冒号表示嵌套路径
get_var("Bob:a", default)  # 取不到返回默认值
has("Bob") / delete("Bob") / delete_all
save()                     # 真正写盘
```
- 支持嵌套变量、Resource、Array；**整个存档是单一加密文件**，密钥由「玩家的唯一 OS ID」派生（README 明示：玩家之间无法交换存档）
- 无 schema 版本/迁移、无多槽位、无自动保存触发机制

对本项目：`set_var` 存 warehouse 数组很方便，但缺少你们明确要求的 **版本字段 + 迁移 + 原子写**，且 OS-ID 派生密钥会让「多人在同一台机器上测试」的存档不可移植（换 Windows 用户即无法读取）。**只推荐用来抄它的 API 设计，不建议作为主方案。**

### 2.4 `fernforestgames/godot-savekit` — API 最优雅，但缺迁移与原子写

- 仓库：https://github.com/fernforestgames/godot-savekit （描述：「Godot 4.5+ addon for saving and loading game state, with pluggable save file formats」）
- 许可证：**MIT** ｜ 规模：15★ / 2 open issues / 创建 2026-03-31 / 最后 push 2026-06-17
- 形态：addon，启用后自动注册 `SaveManager` autoload

API（README 实测）：
```gdscript
SaveManager.save_game(PackedStringArray(["MyGame", "Slot 1"]))  # → user://save_games/MyGame/Slot 1.json
SaveManager.load_game(PackedStringArray(["MyGame", "Slot 1"]))
SaveManager.save_scene_tree_in_memory() -> PackedByteArray
SaveManager.save_scene_tree_to_disk(absolute_path) -> Error
SaveManager.serializer_script = preload(".../binary_serializer.gd")
SaveManager.save_file_extension = ".sav"
```
- 把节点加入 `saveable` 组即可；默认用反射保存 `@export` / `@export_storage` 中与默认值不同的属性；可用 `save_to_dict(s)` / `load_from_dict(s, data)` 完全接管
- 自定义资源继承 **`SaveKitResource`** 即被自动序列化并去重；普通 `Resource`（贴图、场景）只存路径/UID，且只从 `res://` 加载 → README 明确称这是为了规避 `ResourceLoader` 的代码注入风险
- 生命周期信号：`before_save` / `after_save` / `before_load` / `after_load`
- **缺**：schema 版本/迁移、加密、原子写、自动保存（README 未提及 → 未验证/无）

对本项目：如果你们的装备物品做成 `SaveKitResource`（`class_name Item extends SaveKitResource`），序列化体验最好；但「读失败保留旧文件」必须自己加。注意它要求 **Godot 4.5+**。

### 2.5 `Static-Signal/godot-save-vault`（Save Vault）— 纯存储层，加密+线程化自动保存

- 仓库：https://github.com/Static-Signal/godot-save-vault ｜ Asset Library：https://godotengine.org/asset-library/asset/5478 （**1.1.0**，MIT，Tools 4.3，2026-09-22）
- 许可证：**MIT**（README 明确）｜ Star / open issues / 最后提交：**未验证**（GitHub API 限流）
- 形态：addon（`addons/save_vault/`，无编辑器 UI）

API（README 实测）：
```gdscript
var vault := SaveVault.new("your-own-secret-key-here")
vault.save_game(0, {"level": 3, "coins": 120, "saved_at": Time.get_datetime_string_from_system()})
var loaded: Dictionary = vault.load_game(0)
vault.save_async(0, data)           # 工作线程，不卡帧
vault.save_exists(0) / vault.delete_save(0) / vault.wait_for_pending_autosave()
```
- `SaveVault.new(encryption_key, save_dir = "user://saves/", save_extension = "", save_format = "json")`；`"binary"` 走 `var_to_bytes/bytes_to_var`
- 加密用 `FileAccess.open_encrypted_with_pass()`，并**明确说明密钥不是真正的秘密**（可被从导出包中提取），只防「文本编辑器随手改档」——这个定位讲得很诚实
- 每次保存保留上一份为 `.bak`；可选 Steam Cloud 同步（检测到 `Steam` 单例才启用），并用你自己写的 `saved_at` 做云/本地冲突取舍
- 也可用 `SaveVaultNode`（`@export` 配置 + `autosave_interval_sec` + `get_save_data: Callable`）
- **缺**：schema 版本/迁移（README 明确说它「完全不知道存档里装的是什么」）

对本项目：适合当作「会加密、会线程化自动保存、有多槽位和 .bak」的文件 IO 层，然后你们自己在其上写 ~80 行 domain 层（版本号 + 迁移 + 24 格仓库结构）。前提是先核实 star/维护度（未验证）。

### 2.6 `kimbunner/godot_save`（商店名「Addon Save (4.x)」）— 功能堆得最满

- 仓库：https://github.com/kimbunner/godot_save ｜ Asset Library：https://godotengine.org/asset-library/asset/4305 （**1.3**，MIT，Tools 4.1，2026-04-29）
- 许可证：**MIT**（README 明确）｜ Star / open issues：**未验证**
- 形态：addon（`addons/GodotSavesAddon`），节点式组件

API（README 实测）：
```gdscript
$Save.save_data(data, "filename", ".json")
var player_data = $Save.edit_data("player_data", ".json")
$Save.remove_data("player_data", ".json")
$Save.snap_screenshot(get_viewport(), "my_screenshot")
await $Save.upload_save("profile1") / await $Save.download_save("profile1")
```
- 特性：`.sav/.json/.txt`；**可选 AES-256**（key 内部哈希成 32 字节）；可选 ZIP 压缩；**滚动备份 `keep_backups` + `backup_limit`（默认 3）**；`use_auto_save` / `auto_save_interval`（默认 60s）；**README 明确写「Safe Writes（temp + rename system to prevent corruption）」**；非阻塞截图队列；可选云同步
- **缺**：schema 版本/迁移（未提及）

## 4. 「Roll your own」基线：Godot 4 版本化 JSON 存档 + 原子写

以下 API 均已对着 Godot 官方文档源码（`doc/classes/*.xml`）与官方 demo 逐条核实。

### 4.1 官方推荐的数据路径与序列化方式

- 存档写 `user://`。Windows 实际落在 `%APPDATA%\Godot\app_userdata\<项目名>\`（README 实测文本）；`user://` 是跨平台正确做法。
- **设置类数据官方建议用 `ConfigFile`**：`Saving games` 文档原文有 note：「If you're looking to save user configuration, you can use the `ConfigFile` class for this purpose.」
- 官方 `Saving games` 教程的姿态：用 `get_tree().get_nodes_in_group("Persist")` 找可保存对象，每个对象实现 `save()` 返回字典，`JSON.stringify()` 后 `store_line()`；加载时逐行 `JSON.new().parse()` 并检查 `parse_result == OK`。
- **本工作区里就有官方 demo**（可直接阅读，无需联网）：
  - [`loading\serialization\save_load_json.gd`](loading/serialization/save_load_json.gd) —— JSON 方案，含 `var_to_str` / `str_to_var` 处理 Vector2 等非 JSON 类型的技巧，以及 `json.parse()` + `json.get_data() as Dictionary`
  - [`loading\serialization\save_load_config_file.gd`](loading/serialization/save_load_config_file.gd) —— `ConfigFile` 方案，`config.set_value("player","health",...)` → `config.save("user://save_config_file.ini")`
  - Asset Library 条目：https://godotengine.org/asset-library/asset/2781

### 4.2 关键 API（已核实）

```gdscript
# 文本 / JSON
var f := FileAccess.open("user://save_0.json", FileAccess.WRITE)   # WRITE: 存在则截断为 0 长度 ← 崩溃窗口的来源
f.store_string(JSON.stringify(data, "\t"))
f.flush()          # 官方：可用以确保「项目崩溃而非正常关闭」时数据安全
f.close()          # FileAccess 释放时自动关闭；但 F8 强杀进程不会关闭

# 读
var txt := FileAccess.get_file_as_string("user://save_0.json")
var dict = JSON.parse_string(txt)          # 失败返回 null（不提供错误详情）
var j := JSON.new()
var err := j.parse(txt)                    # 返回 Error；失败用 j.get_error_message() / j.get_error_line()
if err == OK: var d = j.data

# 二进制（更小、支持绝大多数 Godot 类型）
f.store_var(value, false)                  # full_objects=true 时允许编码对象
var v = f.get_var(false)                   # allow_objects=true 有官方 RCE 警告，务必保持 false
# 或 var_to_bytes() / bytes_to_var()

# 加密
FileAccess.open_encrypted_with_pass("user://save_0.sav", FileAccess.WRITE, "mypass")
FileAccess.open_encrypted("user://save_0.sav", FileAccess.WRITE, key_32_bytes)   # key 必须 32 字节

# 原子替换（官方 DirAccess.rename：目标存在且未被访问保护时会被覆盖）
FileAccess.open("user://save_0.json.tmp", FileAccess.WRITE).store_string(json)
DirAccess.rename_absolute("user://save_0.json.tmp", "user://save_0.json")

# 目录与完整性
DirAccess.make_dir_recursive_absolute("user://saves")
FileAccess.get_md5(path) / FileAccess.get_sha256(path)     # 可做校验侧车文件
FileAccess.create_temp(mode_flags, prefix, extension, keep) # 官方也提供临时文件 API
```

### 4.3 已核实的坑（写进你们的代码审查清单）

1. **`JSON.stringify` 会把所有数字转成 float**（官方原文：JSON 规范只定义 number，转换时所有数值都会变成 float）→ 物品的 `quality:int` 读回来可能是 `3.0`。要么读时用 `int()` 显式转换，要么用二进制 `store_var`。
2. **`FileAccess.WRITE` 会先把文件截断为 0 长度** → 这正是「写到一半崩溃就毁档」的根因，所以必须走 `.tmp` + `rename_absolute` 替换。
3. **`get_var(allow_objects=true)` / `store_var(full_objects=true)` 有官方 RCE 警告**：「Deserialized objects can contain code which gets executed.」→ 永远传 `false`。（关于 `ResourceLoader` 加载外部 `.tres` 的同类风险：SaveKit README 明确把它列为设计动机；官方 ResourceLoader 页面的逐字警告本次未核实，标注为**未验证措辞**。）
4. **`JSON.parse_string` 失败只返回 null，不给原因** → 「读失败要保留旧文件」的场景请用 `JSON.new().parse()` + `get_error_message()`，才能把诊断信息写进日志。
5. **`eof_reached() == false` 不能用来判断「还有数据」**，官方要求用 `get_position() < get_length()`。
6. `FileAccess` 在 `F8` 强杀时不会正常关闭 → 关键节点主动 `flush()`。

### 4.4 JSON vs 二进制 vs `ResourceSaver` 取舍

| 维度 | JSON（`JSON.stringify`） | 二进制（`store_var` / `var_to_bytes`） | `ResourceSaver` / `ResourceLoader` |
|------|--------------------------|----------------------------------------|-------------------------------------|
| 可读/可调试 | ✅ 最好（能直接看、能 diff） | ❌ | ⚠️ `.tres` 可读，`.res` 不可读 |
| Godot 类型支持 | ❌ 不支持 Vector2/Color/Quaternion，整数变浮点 | ✅ 支持大多数类型 | ✅ 最完整（含资源引用） |
| 代码注入风险 | 无 | `allow_objects=false` 时低 | ⚠️ 最高（外部资源可带脚本） |
| 版本迁移难度 | 低（字典好改） | 中 | 高（类结构绑定） |
| 适合本项目 | ✅ 存档小、需要人工排查 | ✅ 想要更小/更严谨 | ❌ 不建议存玩家数据 |
| 官方定位 | 「简单游戏状态」适用，但局限多 | 「更复杂或更大」的推荐替代 | 面向 `res://` 资产 |

官方 `Saving games` 文档原文结论就是：JSON 适合简单状态且便于调试，但类型与体积有局限；更复杂/更大的状态应改用二进制序列化。

### 4.5 自研版最小设计（约 200–300 行）

```gdscript
# res://autoload/save_manager.gd  (autoload 名: SaveManager)
extends Node

const SCHEMA_VERSION := 2
const SLOT_COUNT := 3
func _slot_path(i: int) -> String: return "user://saves/slot_%d.json" % i

func save_slot(i: int, data: Dictionary) -> bool:
    data["schema_version"] = SCHEMA_VERSION        # ① 版本字段永远写进去
    data["saved_at"] = Time.get_datetime_string_from_system()
    DirAccess.make_dir_recursive_absolute("user://saves")
    var tmp := _slot_path(i) + ".tmp"
    var f := FileAccess.open(tmp, FileAccess.WRITE)
    if f == null: return false
    f.store_string(JSON.stringify(data, "\t"))
    f.flush(); f.close()                            # ② 先落盘到临时文件
    if FileAccess.file_exists(_slot_path(i)):
        DirAccess.rename_absolute(_slot_path(i), _slot_path(i) + ".bak")  # ③ 保留旧档
    return DirAccess.rename_absolute(tmp, _slot_path(i)) == OK            # ④ 原子替换

func load_slot(i: int) -> Dictionary:
    var path := _slot_path(i)
    if not FileAccess.file_exists(path): return _new_save()
    var j := JSON.new()
    if j.parse(FileAccess.get_file_as_string(path)) != OK:
        # ⑤ 读失败：保留原文件，另存为 .corrupt 供事后分析，然后生成新档（绝不覆盖）
        DirAccess.rename_absolute(path, path + ".corrupt_%d" % Time.get_unix_time_from_system())
        push_warning("Save corrupt: %s @ line %d" % [j.get_error_message(), j.get_error_line()])
        return _new_save()
    var d: Dictionary = j.data
    var v := int(d.get("schema_version", 1))
    while v < SCHEMA_VERSION:                       # ⑥ 逐级迁移
        d = _migrate(v, d); v += 1
    return d

func _migrate(from_version: int, d: Dictionary) -> Dictionary:
    match from_version:
        1: d["warehouse"] = d.get("warehouse", [])   # 示例：1→2 新增仓库字段
    return d

func _new_save() -> Dictionary:
    return {"schema_version": SCHEMA_VERSION, "warehouse": [], "unlocks": {},
            "tutorial_flags": {}, "records": {}}
```
再配一个 `settings.cfg`（用 `ConfigFile`，与存档分离：音量/分辨率/按键），以及一个自动保存去抖：`_dirty = true` → `await get_tree().create_timer(2.0).timeout` → 检查 `_dirty` 再落盘。

### 4.6 最后裁决：用 addon 还是自己写 200 行？

**我的建议是「自研为主，参考 savestate/locker 的设计」**，理由：

1. 你们的存档是**纯数据**（24 格物品的字典数组、解锁标记、布尔 flag、纪录），没有「场景里任意节点状态」的复杂需求 —— 而多数 Godot 存档插件（GDSave、SaveKit、game_state_saver）的主要价值恰恰在于「节点/场景状态自动序列化」，**这部分你们用不上**。
2. 你们真正难的三点（schema 版本迁移、原子写、损坏时保留旧档）**自研各 10–30 行就能写对**，且代码量小到能被组内 3 个人全部读懂 —— 对课程答辩/代码评审是加分项。
3. 自研 = 零依赖、零版本漂移、零许可证顾虑。
4. 但如果你时间很紧（只想 1 天内搞定并且不想管 IO 细节），**`savestate` 的 Lite 版是唯一把你们需求清单逐条对上且实测支持 4.7 的现成插件**，值得用；把它的 2.0.0 版本冻结并提交进仓库即可。
5. `ForgeJSONGD`（111★，MIT）可作为可选助手：当物品字典里想塞 Godot 原生类型时省掉手写 encode/decode。
