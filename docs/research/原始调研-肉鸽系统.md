## 1. 房间/区块化程序化关卡生成（手工模板 → 固定槽位拼接）

设计约束是「8 个手搓模板 + 固定槽位 + 不自由拓扑 + 不运行时烘焙 navmesh」。**这个约束下第三方生成器基本都不对口。**

### 1.1 alexishachemi/godot-procgen（ProcGen）

- URL：https://github.com/alexishachemi/godot-procgen ｜ 资产库 https://godotengine.org/asset-library/asset/4672
- 许可证：**MIT** ｜ Godot：**最低 4.5** ｜ Star 9 ｜ 创建 2026-01-09，最后推送 **2026-01-14**（资产库 1.3，2026-01-15）
- 提供：Room-based Dungeon & cave（GDScript 重写自作者自己的 ProcGen）。算法链：**BSP 分区 → Kruskal 最小生成树连房间 → A\* 通走廊 → 元胞自动机做自然地形 → flood fill 去封闭区 → 边缘平滑**。
- API（README 原文）：`map_size`、`room_amount`、`automaton_iterations`、自定义 `seed`、`generate_new_seed_on_run`；`generate()`；查询 `is_full_at()` / `get_rooms()` / `get_corridor_areas()`；`ProcGenVisualizer` 可视化调试；检查器有 Generate 按钮。
- 安装：资产库下 `addons.zip`（releases/download/1.3）→ addons → 启用。
- 坑：**生成「随机房间」，不是「从你手搓的 8 个模板里挑」**——与核心约束相反。输出是网格数组，**贴图要自己写 TileMapLayer**（Godot 4.3 起 `TileMap` 被 `TileMapLayer` 取代）。README 自警告 `automaton_threads` 多线程**「相当不稳定且低效」**，建议保持 1。

### 1.2 krazyjakee/DungeonTemplateLibrary-Godot（DTL）

- URL：https://github.com/krazyjakee/DungeonTemplateLibrary-Godot ｜ 商店 https://store.godotengine.org/asset/jake-cattrall/dtl/
- 许可证：**MIT** ｜ Godot：**最低 4.5**（商店 "Works with 4.3 and up" 与 "Minimum Godot Version: 4.5" 冲突，保守取 4.5）｜ Star 53 ｜ 最后推送 2026-06-11 ｜ 版本 **0.0.4-citest**（CI 预发布，无 changelog）
- 提供：**GDExtension（C++）**包装 C++ 库 DungeonTemplateLibrary，单个 `DTL` 类，15+ 算法：`RogueLike` / `SimpleRogueLike`（房间+走廊）、`MazeBar` / `MazeDig` / `ClusteringMaze`、`PerlinIsland` / `FractalIsland` / `SimpleVoronoiIsland` / `CellularAutomatonIsland` 等。每方法返回 **1D `[w*h]` 数组**。
- 坑：同样是「程序生成算法」而非「模板拼装」，**解决不了模板需求**。当前是 **0.0.4 预发布 + 商店明确标注 "This Item Uses AI"**。商店示例用的是旧 `TileMap.set_cell(0, Vector2i, id)` 签名，**照抄会报错**。

### 1.3 RickyYCheng/Edgar.Godot（概念最对口，技术栈不对）

- URL：https://github.com/RickyYCheng/Edgar.Godot
- 许可证：**MIT**（逐字确认 "Copyright © 2025 RickyYC"）｜ Star 23 ｜ 创建 2025-02-28，最后推送 2026-06-16，默认 `main`
- 提供：**真正的「手工房间模板 + 图约束」生成器**。文件树核到：`addons/edgar.godot/edgar.godot.gd`、`edgar_graph_resource.gd` + `edgar_graph_importer.gd`、`edgar_renderer_2d.gd`(15KB)、`edgar_post_processor.gd`、`fog_of_war/`(`fog_of_war_sprite_2d.gd` 10.6KB + `fow_blur.gdshader`/`fow_show.gdshader`)；内核有 **`RoomTemplate.cs` / `RoomTemplateInstance.cs` / `MapDescription.cs` / `BasicRoomDescription.cs` / `CorridorRoomDescription.cs` / `Room.cs` / `LayoutOperations.cs` / `RoomShapesHandler.cs` / `FixedRoomsChainDecomposition.cs`**。
- 致命坑：**内核全 C#（.NET）**——`kernel/EdgarGodot.cs`、`EdgarGodotGenerator.cs`，以及 `kernel/edgar.aot/**` 下大量 .cs。**GDScript 团队无法使用**，须切 Godot .NET 版。仓库体量极大（ungh 文件清单 >50KB JSON 被截断）。
- 结论：**读概念可以（模板+槽位+图约束+固定房间分解），别接。**

### 1.4 其余核过的

- **majikayogames/SimpleDungeons**：许可证 **CC0-1.0**（逐字确认）、Star **410**、最后推送 2025-04-02。但**纯 3D**：`DungeonGenerator3D.gd`(44KB) / `DungeonRoom3D.gd`(19KB) / `DungeonAStarGrid3D.gd` / `CSGStairMaker3D.tscn` / `FPSController`。**2D 零复用**，写进来是防止团队被 410★ 骗进去。
- **loothammer/godot_2D_procedural_dungeon_gen**：Star 2，仅一次提交 2025-06-25，未深入验证，价值低。
- **未发现任何依赖运行时 navmesh 烘焙的候选**；「每模板预置 NavigationRegion2D + 编辑器期烘焙 + 运行时拼接」与所有候选都不冲突。

### 推荐

**自己写，不要接第三方。** 三条硬约束把问题压缩成「从固定槽位表里挑并拼接」，而现成生成器解决的是完全相反的「自由拓扑随机房间」。

建议实现（约 150–250 行 GDScript，1.5–2 人日）：

1. 每模板一个 `.tscn`，根 Node2D，内部固定命名槽位 `Marker2D`（`Slot_N/E/S/W`）。
2. 模板库 `Array[PackedScene]` + 每模板一个 `Resource` 声明尺寸、可用槽位方向、地板类型（战斗区/走廊/仓库）。
3. 槽位匹配表：新房间 `Slot_W` 对齐已放房间 `Slot_E` 的世界坐标；`Dictionary[Vector2i, RoomInstance]` 做占用网格防重叠——确定性、可复现、易调试。
4. 导航：模板内预置 **NavigationRegion2D 编辑器期烘焙**（存进 `.tscn`），运行时多个 region 放进**同一 NavigationServer2D map**（`map_force_update()`）。Godot 4 会把同 map 多 region 合并为连通图（**建议第一周做 30 分钟连通性冒烟测试确认**）→ 天然满足「不运行时烘焙」。
5. 两个战斗区：模板数据打 `region_tag`，生成时约束「至少 2 个 combat 房间」；房间不加载/卸载，只切相机边界 → 正好复用第 3 区 Phantom Camera 的 priority 切换。

只有**放弃「手搓模板」改全程序化**时才考虑第三方，那时首选 **ProcGen**（MIT、4.5、GDScript、无二进制依赖）。

### 2.4 声音传播 / 听觉警觉：**没有找到可靠现成件**

- `Stuyk/GigaAudio-Godot`（https://github.com/Stuyk/GigaAudio-Godot）：Star 94、「audio occlusion … Godot **4.3+**」、最后推送 **2025-02-21**（停更约 20 个月）、**许可证未验证**。做的是**音频遮挡**，不是给 AI 派发警觉事件。
- `stechyo/godot-steam-audio`、`undomick/godot-nexus-resonance`：Valve Steam Audio 集成，**面向 3D**，过重，许可证与 Godot 版本未验证。
- `Jhon-Crow/godot-topdown-MVP` 确有声音警觉（搜索命中其 PR 标题："enemies now hear breaching charge explosions"、"enemies now correctly react to player sounds"），但**该仓库无 LICENSE（404）**，只能看思路。

**建议自己写（1–2 人日）**，也是最能做差异化的地方：

- `NoiseEmitter` + `SoundEventBus` autoload：推 `{position, loudness, source_faction}`；
- 敌人订阅 → 距离衰减算警觉增量 → 写入**所在房间的 AlertLevel** → 超阈值通知同房间同伴（这就是 propagation）；
- 警觉状态驱动 `NavigationAgent2D.set_target_position()`，配 `avoidance_enabled` 做同伴避让。

## 3. 2D 相机：跟随 + 鼠标 look-ahead + 屏幕抖动 + 房间边界夹紧

### 3.1 ramokz/phantom-camera

- URL：https://github.com/ramokz/phantom-camera ｜ 文档 https://phantom-camera.dev/
- 许可证：**MIT** ｜ Godot：**最低 4.4**（README 徽章 "Godot-4.4+"）｜ Star **3598**、Fork 142 ｜ 创建 2022-10-29，最后推送 **2026-10-07**，默认 `main`
- 节点：`PhantomCamera2D`/`PhantomCamera3D` + **`PhantomCameraHost`** 管理 `Camera2D`/`Camera3D`。特性（README 逐条核过）：
  - **Priority**：多相机按优先级生效，切换**无缝过渡**；
  - **Follow Mode**：`Glued` / **`Simple`（offset 偏移 + 可选阻尼）** / `Group`（多目标中心）/ `Path` / **`Framed`（水平/垂直 dead zone 动态取景：目标移动超出死区前相机不动）** / `Third Person`（仅 3D）；
  - **Zoom (2D)**；**Look At**（仅 3D）；**Tween** 切换曲线可调；**Viewfinder** 预览。
  - 示例场景 `res://addons/phantom_camera/examples`（2D + 3D）。
- 安装：AssetLib 搜 "Phantom Camera" → **只勾 `phantom_camera` 目录** → 启用；或 Releases zip 拷 `addons/phantom_camera`。
- 适配：**直接命中「跟随 + 鼠标偏移 + 房间边界」**——look-ahead = `Simple` follow 的 offset（鼠标位置映射成小偏移+阻尼）；房间边界 = limit + **Priority** 在房间间切换（两战斗区各布一个 PhantomCamera）。`Framed` 死区还能做出「小幅移动不晃镜头」的高级感。
- 坑：README 特性表**没有 screen shake/noise** → **抖动不要指望它，另配 3.2**。

### 3.2 filipbasara/trauma-gd（Trauma）

- URL：https://github.com/filipbasara/trauma-gd
- 许可证：**MIT** ｜ Godot：**最低 4.4**（README 明确："Godot 4.4 or newer. The plugin references its resources by `uid://`, which earlier versions don't resolve."）｜ Star 4 ｜ 创建 2026-03-22，最后推送 **2026-07-27**
- 提供：**`CameraShake` 节点**挂 `Camera2D` 下即可。API：`shake(profile)` 传 `ShakeProfile`；或 `add_trauma(0..1)` 累积（每中一枪 `add_trauma(0.25)`，4 枪满）。`ShakeProfile` 字段：`intensity` / `rotation_intensity` / `decay_rate` / `frequency` / `initial_trauma`。模型：**`shake_amount = trauma ^ profile.trauma_exponent`**，trauma 按 `decay_rate`/秒衰减，多次调用**叠加封顶 1.0**。自带 `presets/{explosion, earthquake, impact, jitter, rumble}.tres`。
- 坑（README 明确警告）：**`Camera2D.ignore_rotation` 在 Godot 4 默认开启，会丢弃相机旋转**。只想用 offset 抖动没问题；想让 `rotation_intensity` 生效必须**关掉它**，否则插件 push 一条 warning。

### 3.3 Godot 4 内置 Camera2D（零依赖方案，别忽略）

`Camera2D` 已内置 `position_smoothing_enabled`/`position_smoothing_speed`、`drag_horizontal_enabled` + `drag_left/right/top/bottom_margin`（死区取景）、`limit_left/right/top/bottom` + `limit_smoothed`（房间边界夹紧）、`offset`（look-ahead）。

**若 7 周里相机不是亮点，内置 + 手写 20 行 offset/shake 反而最快**；Phantom Camera 的价值在多相机 priority 切换与 tuned 过渡。

### 推荐

**Phantom Camera 做跟随与多房间切换 + trauma-gd 做抖动**；鼠标 look-ahead 用 Simple follow 的 offset 自做映射。预算：接 Phantom Camera 半天 + trauma 1 小时。时间紧则退化为「内置 Camera2D + 20 行 offset/shake」。

## 4. 攻击盒/受击盒 + 阵营与层

### 4.1 cluttered-code/godot-health-hitbox-hurtbox（最贴需求）

- URL：https://github.com/cluttered-code/godot-health-hitbox-hurtbox ｜ Demo https://cluttered-code.itch.io/godot-health-hitbox-hurtbox-hitscan ｜ Wiki: /wiki
- 许可证：**MIT** ｜ Godot：**最低 4.5**（徽章 "Godot-4.5+"）｜ Star **173**、Fork 9 ｜ 创建 2023-07-20，最后推送 **2026-07-22**（CI + gdUnit4，维护活跃）
- 提供（README + 文件树核过），addon 路径 `addons/health_hitbox_hurtbox/`：
  - **Health**：`health/health.gd`(8.7KB)，current/max、conditions、可选 modifiers；信号覆盖 damage/heal/death/revival 与边界（`damageable`/`healable`/`killable`/`revivable`）。
  - **HitBox**：`2d/hit_box_2d/{basic_hit_box_2d.gd, hit_box_2d.gd}`（+ 3D 同构）。
  - **HurtBox**：`2d/hurt_box_2d/{basic_hurt_box_2d.gd, hurt_box_2d.gd}`。
  - **HitScan**：`2d/hit_scan_2d/{basic_hit_scan_2d.gd, hit_scan_2d.gd}`，**继承 `RayCast2D`**，需主动调 `fire()`；编辑器强制开启「可与 area 碰撞」。
  - **资源**：`resources/health_action.gd`（`HealthAction`：`affect`/`type`/`amount`）、`health_action_type.gd`（`HealthActionType`，如 `KINETIC`/`MEDICINE`）、`health_modifier.gd`（`HealthModifier`：`incrementer`/`multiplier`/convert）、`health_modified_action.gd`。
  - **管线**：`HitBox/HitScan` 发 `HealthAction[]` → `HurtBox` 用自己的 `modifiers` 包装 → `Health` 合并自身 `modifiers` → 应用。
  - 简单/进阶差异：`BasicHitBox2D` = `affect` + `amount`；`HitBox2D` = `Array[HealthAction]`；`BasicHurtBox2D` = 伤害/治疗倍率（还能**反转伤害↔治疗**）；`HurtBox2D` = 按 action type 配 `modifiers`。
- 安装：AssetLib 搜 `Health`/`HitBox`/`HurtBox` → 下载 "Health, HitBoxes, HurtBoxes, and HitScans" → 启用插件。
- 适配/坑：

**本次推荐的所有候选都没有使用 `KinematicBody2D`、`yield`、`Spatial`**（都不是 Godot 3 代码）。但以下红旗必须逐条确认：

| 红旗 | 具体位置 | 后果 |
|---|---|---|
| **拉错分支 → Godot 3 代码** | **bitbrain/beehave** 默认分支是 `godot-4.x`，但仓库**同时存在 `godot-3.x` 分支**（README 直接给两个 zip 链接） | 拉到 3.x = `KinematicBody2D`/`yield`，Godot 4 完全跑不起来 |
| **文档示例是 Godot 3 API** | **peter-kish/gloot** README 的 `deserialize()` 示例：`var res: JSONParseResult = JSON.parse(json)` | Godot 4 已删除 `JSONParseResult`；须改 `JSON.parse_string()`/`JSON.new().parse()`。照抄报错 |
| **GLoot v2/v3 不兼容** | gloot `docs/gloot_2_to_3_transition_guide.md` | 网上多数教程是 v2 写法 |
| **`TileMap` vs `TileMapLayer`** | Godot 4.3 起 `TileMap` 被 `TileMapLayer` 取代 | **ProcGen / DTL 只输出网格数组，贴图要自己写**；DTL 商店示例还是旧 `TileMap.set_cell(0, Vector2i, id)` 签名 |
| **C#/.NET，不是 GDScript** | **GunfireDungeon**（4.4 mono + .NET 9）、**Edgar.Godot**（内核全 .cs） | 需 Godot .NET 版 + .NET SDK；GDScript 团队不能用 |
| **假设 3D** | **SimpleDungeons**（`DungeonGenerator3D`/`DungeonRoom3D`/`CSGStairMaker3D`/`FPSController`）；**godot-steam-audio**/**godot-nexus-resonance**；Phantom Camera 的 Look At / Third Person 仅 3D | 2D 项目零复用 |
| **许可证地雷** | **GunfireDungeon = AGPL-3.0**；**Twin Stick 2D Shoot Em Up (1659) = Proprietary**；**godot-topdown-MVP / arena-survivors = 无 LICENSE（404）** | AGPL 传染；Proprietary 与无授权均**不得复制代码** |
| **GDExtension 二进制依赖** | **LimboAI**、**DTL**（均 C++ GDExtension） | 导出 Windows 必须确保 `.dll` 随包，否则导出后功能静默失效 |
| **破坏性版本迁移** | **cluttered-code v5** 给简单节点加 `Basic*` 前缀 | 混用 v4/v5 会找不到节点类；升级要先到 v4.4.0 |
| **freemium 天花板** | Health & Damage Lite（**最多 4 种伤害类型**）、Equipment Lite（**双手冲突/修饰符聚合在 PRO**）、Saltmire Hitbox（teams 在付费版） | 需求会正好撞天花板 |
| **未发现依赖运行时 navmesh 烘焙的候选** | — | 「模板内预置 NavigationRegion2D + 编辑器期烘焙 + 运行时同 map 合并」与所有候选不冲突（**第一周做连通性冒烟测试**） |

## 8. 哪些能省最多时间（最终排序）

**T0 · 立刻接，回报最高（合计省约 8–12 人日）**

1. **ramokz/phantom-camera**（MIT / 4.4+ / 3598★）—— 跟随、死区取景、多房间 priority 切换、tween 过渡全现成。省 ~2 人日。**接它 + 手写 20 行鼠标 offset。**
2. **cluttered-code/godot-health-hitbox-hurtbox**（MIT / 4.5+ / 173★）—— Health / HitBox2D / HurtBox2D / HitScan2D + 类型化 `HealthAction` + `HealthModifier` 管线。省 ~3–5 人日。**锁版本（v5 有改名）。**
3. **Kelpekk/Juicee**（MIT / 4.2+，screen shake + **hit-stop** + damage numbers）**或 Saltmire Juice**（MIT / 4.6）—— 直接给「完美格挡顿帧」，省 ~1–2 人日。**二选一。**
4. **sempitern0/Lootie / ninetailsrabbit/lootie**（MIT / 4.4 main / 123★）—— Resource 驱动掉落表 + rarity 10 档 + 可复现 seed + `is_unique`。省 ~2 人日。**停更一年，锁 commit 自测 4.7。**
5. **filipbasara/trauma-gd**（MIT / 4.4+）—— 1 小时接完（选了 Juicee 可省）。

**T1 · 值得接，看时间预算**

6. **peter-kish/gloot**（MIT / 4.4+ / 982★）—— 背包 + ItemSlot + GridConstraint + **serialize/deserialize（autosave/黑盒/死亡掉落关键）** + Prototree inherits。省 ~3–5 人日，但 **API 面积大、v2/v3 不兼容、README 示例是 Godot 3 写法**。若只要「24 格仓库 + 4 槽 + 存盘」，**自己写 200 行 Dictionary + Resource 可能更快**。
7. **d-bucur/godot-vision-cone**（MIT+Apache / 4.0+ / 94★）—— 视野锥 + 编辑器可视化 + 遮挡正确，省 ~1–2 人日。**但「声音传播/警觉传播」无现成件，必须自研（1–2 人日）**——这反而是最该投时间做差异化的地方。
8. **bitbrain/beehave**（MIT / 4.2 / 3294★，**记得拉 `godot-4.x`**）—— AI 状态超 5 个或第 4 周状态机要炸时再上。**7 周项目先手写 enum 状态机通常更快**。**LimboAI**（MIT / **4.6+** / 3048★）更强但 GDExtension + 学习曲线更陡。

**T2 · 不要接（每种都有硬拒绝理由）**

9. **xlljc/GunfireDungeon**（340★）—— **AGPL-3.0 + C#/.NET 9**。可读设计，**不能进代码库**。
10. **RickyYCheng/Edgar.Godot**（23★、MIT）—— 概念最对口，但**内核全 C#**，GDScript 团队不可用。
11. **majikayogames/SimpleDungeons**（410★、CC0）—— **纯 3D**，2D 零复用。**Star 数会骗人。**
12. **Twin Stick 2D Shoot Em Up（asset 1659）**—— **Proprietary 专有许可**。
13. **Jhon-Crow/godot-topdown-MVP（3★）、NachoKai/arena-survivors（10★）**—— **均无 LICENSE（404）**，只能借鉴「模式」不能复制代码。
14. **godot-arpg-kit（15★、MIT、中文文档）**—— 放 T2 唯一原因是**太新太小无社区验证**；但**中文文档 + 组件化 + 189 测试 + 中文 postmortem** 可读性极高，**建议作为「参考文献」通读**（尤其 `docs/Loot掉落系统使用文档.md`、`docs/Combat战斗系统使用文档.md`），而不是当依赖。
15. **DTL（53★、MIT、GDExtension）**—— 版本仍是 `0.0.4-citest` 预发布 + 商店标注 AI 生成，风险高于收益。

**区域 1 最终建议（重复强调）**：「8 个手搓模板 + 固定槽位 + 无自由拓扑 + 不运行时烘焙 navmesh」的设计**本身就是最省时间的方案**。**不要为了「用上开源」去接生成器**——自己写 150–250 行槽位拼接（1.5–2 人日）比集成 Edgar（C#）或 DTL（预发布 GDExtension）更快、更可控、更符合验收。

## 9. 建议的 7 周接入顺序

| 时间 | 动作 | 依赖 |
|---|---|---|
| 第 1 周 | 锁 Godot 版本（建议 **4.6.x 或 4.7.x**）；装 Phantom Camera + trauma-gd + Juicee；跑通「移动 + 鼠标瞄准 + 跟随 + 抖动 + 顿帧」 | 无 |
| 第 1 周 | **同时**做房间模板槽位拼接原型（8 模板 → 固定槽位）+ NavigationRegion2D 同 map 连通性冒烟测试 | 无 |
| 第 2 周 | 接 cluttered-code 一套；定 **Layer Names 约定**；做方向性格挡 + 完美格挡窗口 + 弹反（自研，最大工作量点） | 第 1 周层约定 |
| 第 3 周 | 接 Lootie 做掉落表；自写 `AffixPool` Resource；武器 heat/overheat（自研纯数值） | — |
| 第 4 周 | Vision Cone + **自写 NoiseEmitter/AlertLevel 警觉传播**；AI 状态机（先 enum，复杂了再上 Beehave） | NavigationAgent2D |
| 第 5 周 | GLoot 背包 + ItemSlot 装备槽 + `serialize()` 接 autosave / 黑盒 / 死亡掉落（**风险点，留缓冲**） | 第 3 周物品模型 |
| 第 6–7 周 | P1：合成/天赋核心/无人机/拆解/保险丝/NPC 救援/结算评级（**全部自研，无开源可借**）；调优与打磨 | — |

**一句话总结**：**相机、打击/血量、Juice（顿帧/抖动/伤害数字）、掉落表**这四块开源能实打实省下 8–12 人日；**房间生成、声音警觉传播、方向性格挡弹反、词缀合成**这四块**没有可用开源件，必须自研**；而看起来最像「现成答案」的 GunfireDungeon 因 **AGPL + C#** 必须放弃。
